# 도깨비 복 주머니 효과 — 작업37

준비 중 보유 주머니를 사용하면1개를 소비하고 일반재화100/150/200/250/300 중 하나를 각각20% 확률로1회 지급한다. 아이템 추첨·추가 보유 지급·재입고는 없다. 특별재화와 다른 아이템·천운부 적용 상태·기존 윷 결과는 유지한다.

기존 사용 실행기와 보유 선회수/실패 복원/재입력 잠금을 사용한다. 정수 Random.Range(0,5)의5개 동일 확률 구간을 보상100+인덱스×50에 대응시킨다. 일반재화 HUD는 기존 Changed 경로로 갱신한다. 최대 보상300 전액을 받을 공간이 없으면 추첨 전 무소비/무지급으로 거부한다. 다른 효과38~39는 후속이다.

## 실행 흐름

1. InventoryUI.UseSelected→StageItemUseController.TryUse의 준비/보유/실행 조건 검사를 거친다. 처리 중 IsUsing을 유지하고 보유를 알림 없이 회수한다.
2. [DokkaebiPouchEffect](../Assets/Scripts/Turn/DokkaebiPouchEffect.cs)는 사용 실행기와 일반재화를 명시적 참조로 받는다. OnEnable/OnDisable에서 등록/해제하고 외부의 직접 효과 호출이나 지급 콜백의 재호출은 거부한다.
3. TryApply 안에서 정수 Random.Range(0,5)를1회 호출한다. 정수 상한5는 제외되므로5개의 같은 확률 결과이며 reward=100+index×50으로 각각100/150/200/250/300에 대응한다. StageCurrency.Grant(reward)가 일반재화를 지급하고 기존 Coin HUD를 갱신한다.
4. 잔액 알림 시점에는 주머니가 이미 보유에서 제거돼 있다. 성공 후 보유 변경 알림으로 선택과 슬롯을 갱신한다. 구매 완료 이력을 지우거나 새 품목을 추가하지 않는다. 천운부 할인과 특별재화도 유지한다.
5. [DokkaebiPouchBuilder](../Assets/Editor/DokkaebiPouchBuilder.cs)가 실제 씬에 효과를 추가하고 사용 실행기/재화를 연결한다. 저장 후 씬을 다시 열어 참조를 검사한다. 기존 UI 크기·배치는 바꾸지 않는다.

검증은 난수 상태를 고정해5개 결과를 각각 실제 구매→인벤토리 선택→사용 버튼으로 확인한다. 이는 보상 매핑과 지급/소비를 확인하는 결정적 검사이며 표본 빈도로20%를 추정하는 검사가 아니다. 확률은 동일 크기의 정수5구간으로 정의된다.

## 검증

[실제 ThrowYut Play Mode101개 검사 통과·검사 구간 오류0](Verification/DokkaebiPouchVerification.json). [검증 코드](../Assets/Editor/DokkaebiPouchVerification.cs).

- 실제 천운부/주머니 구매→보유 슬롯 선택→사용 버튼 클릭으로5개 보상100/150/200/250/300을 각각 확인했다. 일반재화 변경/보유 변경 알림은 각각1회이며 HUD·이미 제거된 주머니를 함께 관찰한다.
- 재화 알림 안의 사용 실행기/직접 효과/구매/일반·특별 소환/윷/전투 재입력을 거부한다. 연속/늦은 입력은 추첨도 다시 하지 않는다.
- 주머니 외 새 아이템은 생기지 않고 원래 천운부1개/할인16/특별재화45를 유지한다. 모든 상품 구매 이력은 사용 전후 동일하며 주머니는 계속 품절이다.
- 닫힌 창·일시정지·던지기·승패·비활성 효과/지갑/보유/실행기·정수 상한·실제 전투를 거부한다. 일부 상태는 메모리 fixture다.
- 실제 다음 웨이브 준비에서는 사용을 허용하고 기존 확정 윷 결과를 보존한다. 새 씬의 일반120/특별0/보유0도 확인했다.

첫 실행에서는 현재 씬에 천운부 비용/첫 상품 선택 표시의 참조 누락이 있어 실패했다. 기존 비용 생성기를 재적용하고 선택 표시 참조를 다시 연결한 뒤, 저장/재로드한 씬에서 전체 검사를 통과했다. 참조 누락 원인은 확정하지 않았다. 선택 표시 이미지 파일도 없는 상태여서, 기존 버튼 이미지를 반투명 선택 표시로 재사용하도록 생성기를 보완해 흰 사각형을 제거했다. 초기 UnityEditor.Search 인덱스 예외는 게임 검사 구간 앞이며 오류0은 게임 검사 구간을 뜻한다.

1920×1080 렌더링: [사용 가능 주머니](Previews/DokkaebiPouchReady.png)·[300 지급 후](Previews/DokkaebiPouchGranted.png). 후자 일반재화400은 테스트용400에서 천운부100/주머니200 구매 후300을 받은 결과다. 사용 후 화면의 안내는 검증 콜백에서 전투 재입력을 시도해 생긴 것이다. 테스트 보유/재화/웨이브/난수 상태는 저장하지 않았다. 전체 빌드·수동 완주는 수행하지 않았다.
