# 백호 대장군 — 작업25·26

작업27 갱신(2026-11-19): 실제 씬의 특별소환 실행기에서 후보 추첨·특별재화30 결제·시작 Cell01 여유 인구3 재검사·백호 생성·재입력 보호까지 연결했다. [특별소환 실행 명세](SpecialSummonSpec.md)가 최신 범위이며 아래 ‘27 잔여’는 당시 기록이다. 플레이어용 버튼/창 최종 연결은28에 남는다.

작업26 구현 기준(2026-11-19): 기본 공격마다 실제 좌우9프레임 클립을2초로 재생하고 베는6번째 프레임 시작에 ApplyAttack 이벤트를1회 보낸다. 타격 순간 현재 유효 표적 방향으로 본인 중심 반경3.5·좌우60도(총120도)를 검사해 생존/활성/현재 웨이브 소속 적에게 각각100% 피해를1회 적용한다. 방향 확정 시점과 클립 타이밍은 이번 구현 선택이며 새 사용자 확정 규칙으로 간주하지 않는다. 참격 이동은0.6초 시각 연출이며 추가 피해가 없다. 별도 스킬 버튼/스킬 쿨타임은 추가하지 않는다. 아래25의 ‘공격 실행 비움/26 잔여’는 작업25 시점 기록이다.

2026-11-19. ImplementationGaps 작업25의 실제 유닛·기본 능력치·풀/보드·인구 자리·단독 이동·퇴장·미리보기를 구현한다. 맹호참 클립/부채꼴 타격은 작업26, 특별소환30 결제/후보/생성 UI는27, 정보창/진화 버튼 표시는29~31에 남긴다.

- 기본 공격력100, 공격 간격2초(초당0.5회/DPS50), 사거리3.5. 이번 프리팹은 기존 백호 대기 원본을 표시하고 공격 실행은26까지 비워 둔다.
- 백호 인구는3, 칸 상한은6. 일반3+백호1과 백호2는 허용하며 일반4+백호1과 백호3은 거부한다.
- 업기/진화 불가. 같은 칸의 백호도 선택한1기만 전진·분기·빽도·퇴장한다. 이동 후보와 확정은 인구3을 재검사한다.

- 마지막00 정지는 무보상이며 초과 이동으로 퇴장하면 특별재화15를1회 지급한다. 선택 미리보기는1기/인구3, 후보는 예상 합계/6, 도착 미리보기는+15다.

## 연결

[WhiteTiger](../Assets/Scripts/Ally/WhiteTiger.cs)는 Ally의 PopulationCost/CanStack/CanEvolve/ExitReward를 재정의한다. [YutBoardOccupancy.GetStack](../Assets/Scripts/Yut/YutBoardOccupancy.cs)는 업기 불가 유닛에 선택한1기만 반환한다. [YutActionController](../Assets/Scripts/Yut/YutActionController.cs)는 이 단위를 기존 후보/확정/퇴장/미리보기에 그대로 전달하며 ArrangeAllies는 인구만큼 자리를 배정한다.

[WhiteTiger 프리팹](../Assets/Prefabs/WhiteTiger.prefab)을 씬 YutActionController의 whiteTigerPrefab에 연결한다. 씬의 칸 아래에 미리 놓은 백호도 일반 아군처럼 등록하고 같은 원본으로 풀 반환한다. `DeployAlly(Ally prefab)`는 기존 일반 배치와 공통으로 시작 Cell01/준비 상태/공간 재검사/풀 요청/등록 실패 회수를 제공한다. 개발·검증에서 사용할 수 있으며 플레이어용 특별소환 버튼이나 결제 기능은 아직 연결하지 않는다. 일반 윷 결과별5종 매핑은 유지한다.

개발 확인은 ThrowYut의 `Cells/Cell NN` 아래에 백호 프리팹을 배치하고 Play Mode에 들어가면 된다. 실행 중 개발 코드에서는 `YutActionController.DeployAlly(whiteTigerPrefab)`로 Cell01 배치를 확인할 수 있다. 검증 fixture는 씬에 저장하지 않는다.

## 검증

[WhiteTigerBoardVerification](../Assets/Editor/WhiteTigerBoardVerification.cs)의 실제 씬 Play Mode 검사와 [결과](Verification/WhiteTigerBoardVerification.json), [배치 화면](Previews/WhiteTigerBoard.png), [분기·퇴장 미리보기](Previews/WhiteTigerPreview.png)를 사용한다. 기존 일반 업기/퇴장/미리보기 검증도 회귀 확인한다. 실제 백호 전투·특별소환 결제·전체 빌드는 이 작업의 완료 근거에 포함하지 않는다.

백호52개 검사 통과·검사 구간 런타임 오류0. 초기 실행에서는 동작 검사는 통과했으나 에디터 검색 인덱스의 ArgumentOutOfRangeException2건이 섞여 실패했다. 씬 시작 안정화20회 Editor update 뒤 검사하도록 수정하고 재실행해 통과했으며,게임 예외를 무시하는 필터는 추가하지 않았다.

일반 유닛 회귀는 업기117개·퇴장68개·미리보기65개,합계250개 통과·각 검사 구간 오류0이다. [회귀 결과](Verification/WhiteTigerRegressionVerification.json). 이번 런타임/씬/백호 프리팹/검증 코드7개 파일의 SHA-256이 검증 복사본과 일치하며 `git diff --check`와 변경 문서의 로컬 링크 검사를 통과했다.

## 작업26 맹호참 실행 흐름

1. 기존 `Ally.LateUpdate → RefreshTarget → UpdateAttack`으로 최근접 최초 선택·유효 표적 유지·좌우 모션과2초 공격 간격을 사용한다. 백호는 웨이브 종료 시 첫 공격 대기시간을0으로 돌린다. 일반 유닛의 GAP-028 대조 결과를 수정하는 작업은 아니다.
2. [전투 에셋 생성기](../Assets/Editor/WhiteTigerCombatBuilder.cs)가 기존 백호 이미지로 IdleLeft/Right·AttackLeft/Right 클립과 컨트롤러를 생성한다. 실제 좌우 공격은9프레임이며 베는6번째 프레임에 ApplyAttack 이벤트가 있다. 프리팹 Visual의 `AllyAnimationEvents`가 가상 함수 `WhiteTiger.ApplyAttack`으로 전달한다.
3. 기존 `TryBeginAttackEvent`가 비활성/중복/일시정지/무효 표적을 막는다. 타격 순간 유효 표적이 사망·탈출·사거리 이탈했다면 기존 최근접 재선택을 적용하며 새 표적도 없으면 취소한다. 원점과 방향을 그 순간 고정한다. 표적이 원점과 정확히 겹친 경우 오른쪽을 기준으로 사용한다.
4. `Wave.CollectSectorTargets`가 현재 웨이브 생존 적을1회 순회해 본인 중심 반경3.5 및 방향과의 내적≥cos60°인 대상을 모은다. 경계는 포함하며 부동소수점 오차를 위한 작은 허용값을 사용한다. 콜라이더 수로 피해 횟수를 늘리지 않는다.
5. WhiteTiger는 목록과 각 적의 ActivationVersion을 보관한 뒤 대상별 공격력100%를1회 적용한다. 처리 도중 웨이브가 중단되면 남은 피해를 멈추고,풀에서 재사용된 적은 이전 공격으로 때리지 않는다. 피격으로 바뀐 전투 상태에 따라 이미 판정한 각도를 다시 검사하지 않는다.
6. [WhiteTigerSlash](../Assets/Scripts/Ally/Attack/WhiteTigerSlash.cs)는 기존 참격 스프라이트를0.6초 동안 방향에 맞춰 이동·재생한다. 별도 피해 판정·충돌·투사체를 만들지 않는다. 일시정지 중 연출도 멈추고 웨이브 종료/유닛 비활성/풀 반환 시 숨긴다. 매 공격마다 이펙트 오브젝트를 새로 생성하지 않고 백호 소유 자식을 재사용한다.

자동 검증은 [WhiteTigerCombatVerification](../Assets/Editor/WhiteTigerCombatVerification.cs)에서 실제 클립 이벤트를 기다려 수행한다. 편성·적 위치·일시정지/종료 분기는 검사 중 메모리 fixture이며 씬에 저장하지 않는다. 개별 타격을 수동 함수 호출만으로 대신하지 않는다.

[결과](Verification/WhiteTigerCombatVerification.json)·[실제 참격 렌더링](Previews/WhiteTigerStrike.png).
