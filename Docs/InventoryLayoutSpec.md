# 인벤토리 아이콘·하단 정보 배치 — 2026-11-19

## 변경 이유

슬롯 아이콘이 테두리에 가까웠고, 선택 정보창이 인벤토리 왼쪽에 별도로 열려 윷판을 가렸다. 기존 오른쪽 인벤토리 내부의 하단 빈공간에 정보 영역을 통합한다.

## 화면 배치

- 기존 인벤토리 위치·폭·등장 모션·9칸 배치와 각 슬롯의 클릭 영역은 유지한다.
- 2026-11-19 아이템창_안눌림/눌림은 현재 Single Sprite다. 인벤토리 9칸 기본 배경/Selection을 Single Sprite(fileID 21300000)로 연결한다. 예전 Multiple의 개별 fileID는 사용할 수 없다. PNG와 Single 설정은 유지하고 선택 강조에는 눌림 원본 색을 사용한다.
- 보유 아이콘은 슬롯 중앙 기준 (-2, 2), 60×60로 맞추고 비율을 보존한다. Selection 이미지의 투명 여백을 제외한 테두리 안쪽에 들어오도록 크기를 정한다.
- 선택 정보는 인벤토리 중앙 기준 (0,-300)에 480×300으로 배치한다. 3번째 슬롯 줄 아래이며 창 안쪽에 들어간다. 왼쪽에 뜨던 큰 장식 프레임은 표시하지 않고 얇은 금색 구분선으로 영역만 나눈다.
- 작은 선택 아이콘·아이템 이름·상태를 위에, 배경/효과 설명을 가운데에, 뒤로/사용하기를 아래에 배치한다. 사용/뒤로의 기존 기본·눌림 이미지는 그대로 연결한다. 사용형과 천운부의 버튼 정책도 유지한다.
- 설명은 기존 전체 문구를 유지하며 18~20 크기에서 영역에 맞춘다. 5종 모두 설명 잘림 없이 확인했다. 도깨비 윷/천명전 대기 안내는 정보 영역 아래 (0,-480), 440×36, 글자17로 옮겨 2줄이 겹치지 않게 한다.
- 재화·구매/소비·보유·상점 품절·전투·웨이브·사운드에는 변경이 없다. 테스트 재화/보유는 저장하지 않는다.

## 검증

빈 Owned Icon은 Sprite가 null일 때 Image.enabled=false로 저장한다. 기본 활성 Image는 편집 화면에서 흰 사각형을 그려 슬롯 배경을 가리므로 InventoryBuilder도 초기 비활성으로 생성한다. 런타임 InventoryUI.Refresh가 보유 아이템에 맞춰 다시 활성화한다.

2026-11-19 재연결 수정: 두 PNG가 Single인데 예전 Multiple fileID를 참조해 흰 사각형이 표시됐다. Unity AssetDatabase에서 실제 Single Sprite를 로드해 기본/선택 9개씩 연결하고 현재 씬을 저장했다. 사용자 편집기 Play Mode에서 Inventory Button으로 열어 9개 기본 슬롯의 실제 표시와 흰 사각형 해소를 확인했다. 선택 Sprite는 실제 로드 및 9개 참조를 확인했다. 아이템을 보유·선택하는 시나리오는 이번 재연결 확인에서 실행하지 않았다.

실제 프로젝트의 현재 Assets/ProjectSettings를 동기화한 Unity 6000.3.28f1 검증 사본에서 구매한 5종을 각각 선택해 렌더링했다. [선택 화면](Previews/InventoryLayout/SelectedItem.png).

InventoryVerification은 기존 선택·사용·준비 제한 검사를 유지하고, 구형 외부 프레임 셰이더 검사 대신 하단 정보가 인벤토리 안에 있고 마지막 슬롯 줄 아래에 있는지 검사한다. 화면을 임시 렌더링하기 전 정상 Canvas 좌표에서 검사한다. 기존 도깨비 윷·천명전과 메뉴 검사를 함께 실행했다. 결과는 Docs/Verification에 있다.

## 구현

Assets/Editor/InventoryBuilder.cs가 씬 연결과 배치를 재현한다. 런타임 아이템 기능 코드는 수정하지 않았다. 작업 전 씬과 편집 도구는 작업 산출물의 before 폴더에 별도 보관했다. 이전 미커밋 UI 변경과 사용자가 수정한 유닛/적 프리팹은 보존한다. Git 커밋·업로드는 수행하지 않는다.
