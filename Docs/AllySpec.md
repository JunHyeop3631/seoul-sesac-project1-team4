# 아군 명세

[명세 색인](README.md) · [윷 행동](YutActionSpec.md) · [적군](EnemySpec.md) · [웨이브](WaveSpec.md)

## 종류와 배치

도·개·걸·윷·모 아군은 각각 `Do_Taoist`, `Gae_Warrior`, `Geol_Spearman`, `Yut_Maceman`, `Mo_Archer`이며 공통 [Ally](../Assets/Scripts/Ally/Ally.cs)를 상속한다. 개 아군은 [Gae_Warrior 프리팹](../Assets/Prefabs/Gae_Warrior.prefab)을 사용한다. 소환, 칸 점유, 이동은 [윷 행동 명세](YutActionSpec.md)를 따른다. `YutActionController`는 씬에 미리 배치된 아군과 새로 소환한 아군을 등록하고 대상 탐색에 사용할 `Wave`를 연결한다.

## 문서 상태와 적용 범위

- 2026-11-16 대화에서 확정한 공격 규칙을 아래에 기록한다. 모든 아군의 공격 실행을 Animation Event에 연결했다. 개·걸·윷은 타격 이벤트에서 직접 피해를 주고, 도·모는 발사 이벤트에서 투사체를 생성한다.
- **모(`Mo_Archer`)는 `Mo_Arrow`, 돼지 도사(`Do_Taoist`)는 `Do_Magic`을 사용한다.** 개·걸·윷은 투사체를 사용하지 않는다.
- 대상 탐색은 아래의 기존 규칙을 사용한다. 공통 `Ally`가 대상 갱신·모션 제어·이벤트 중복 방지·공격 간격을 담당하고, 같은 오브젝트의 **`ProjectileAttack` 컴포넌트**가 도·모의 투사체 생성을 담당한다. `Do_Taoist`·`Mo_Archer`는 `Ally`를 직접 상속한다.

## 대상 선택과 유지

- 아군 Animator 상태 이름은 `AttackLeft`·`AttackRight`·`IdleLeft`·`IdleRight`로 통일한다. 코드의 상태 해시 문자열과 다섯 아군 Controller의 상태 이름을 함께 유지한다.

- 웨이브가 실행 중이고 사거리가 양수일 때 대상 확인과 공격을 수행한다.
- 현재 대상이 활성 상태이고 같은 소환 상태이며 XY 평면에서 사거리 안에 있으면 유지한다. 더 가까운 적이 들어와도 대상을 바꾸지 않는다.
- 대상이 없거나 사거리 밖으로 나가거나 비활성화되면 `Wave.FindAttackTarget`으로 새 대상을 찾는다. 적이 풀에서 반환·재사용됐는지는 [적군의 `ActivationVersion`](EnemySpec.md#풀-반환과-재사용)으로 구분한다.
- `Wave`는 프레임의 첫 범위 검색 전에 물리 좌표를 동기화한다. `Physics2D.OverlapCircle`로 적 레이어의 콜라이더를 조회한 뒤, 이번 웨이브에 남은 적 중 중심이 사거리 안에 있는 가장 가까운 적을 반환한다. 제곱 거리가 같으면 인스턴스 ID가 작은 적을 선택한다. 후보가 없으면 다음 프레임에 다시 검색한다.

## 현재 구현: 개·걸·윷의 60프레임 타격 이벤트

- 개(`Gae_Warrior`)·걸(`Geol_Spearman`)·윷(`Yut_Maceman`)의 좌우 공격 클립에 **60프레임(60fps 기준 1초)** 시점의 `ApplyAttack` 이벤트를 등록했다. 게임의 렌더링 프레임 수가 아닌 애니메이션 타임라인의 프레임 번호다.
- 공격 모션 시작 시에는 피해를 주지 않는다. 이벤트 실행 시점에 유효한 현재 대상을 확인하고 `Enemy.TakeDamage`를 호출해 **모션당 한 번** 피해를 준다. 그 순간부터 공격 간격을 계산한다.
- 이벤트 시점에 기존 대상이 무효면 사거리 안의 대체 대상을 찾는다. 목표가 없으면 모션을 즉시 종료하고 피해나 새 대기시간을 만들지 않는다.
- 도·모와 같은 공통 모션 제어를 사용한다. 대상이 바뀌어도 모션 진행률을 유지하고, 반대편이면 진행률을 유지하며 방향을 전환한다. 목표가 없으면 모션을 종료한다. 다음 공격은 모션 종료·타격 이벤트 후 공격 간격 경과·유효한 목표 확보가 모두 충족돼야 시작한다.
- 따라서 기존의 공격 모션 시작 시 즉시 피해를 주는 방식은 더 이상 사용하지 않는다. 처치 후 대상의 유효성을 다시 확인하며 적의 처치와 풀 반환 흐름은 [적군 명세](EnemySpec.md#피해와-처치)를 따른다.

| 프리팹 설정 | 코드 기본값 |
| --- | ---: |
| `Attack Range` | 3유닛 |
| `Attack Damage` | 2 |
| `Attack Interval` | 1초 |

표의 값은 코드 기본값이다. 실제 값은 각 프리팹 Inspector에서 조정한다.

## 확정 규칙: 도·모의 애니메이션 이벤트와 투사체 공격

아래에서 설명하는 화살의 목표·비행·명중·회전·공격 간격 규칙은 도사의 마법 투사체에도 동일하게 적용한다.

### 대상 탐색과 공격 모션

- 공격 가능한 상태에서 사거리 안의 유효한 적을 확보하면 공격 애니메이션을 시작한다. 유효한 적은 활성 상태이고 체력이 남아 있으며 같은 풀 재사용 번호를 가진 적이다.
- 공격 모션 중에도 현재 대상의 유효성을 확인하고, 유지할 수 없으면 사거리 안에서 대체 대상을 찾는다.
- 기존 대상 대신 **바로 다른 유효한 대상을 확보했다면 공격 애니메이션을 처음부터 재생하지 않고 그대로 이어간다.**
- 대체 대상도 없어 **현재 목표가 없으면 공격 애니메이션을 즉시 종료한다.** 목표가 없는데 모션을 끝까지 재생하는 규칙은 사용하지 않는다.
- 목표 변경 자체는 진행 중인 모션을 재시작하거나 공격 대기시간을 초기화하는 사유가 아니다.
- 대상이 반대편으로 바뀌면 **현재 재생 진행률을 유지한 채 반대 방향 공격 모션으로 전환한다.** 처음부터 재생하지 않으며, 방향 전환 때문에 발사 이벤트가 누락되거나 한 모션에서 두 번 발사되지 않도록 한다.

### 발사 이벤트와 목표 확정

- 공격 애니메이션의 발사 장면에 Animation Event를 배치하고, 이벤트에서 화살 투사체를 생성한다.
- 화살의 목표는 **공격 모션 시작 시점이 아니라 발사 이벤트가 실행되는 시점의 현재 대상**으로 정한다. 모션 시작 때의 대상을 이번 공격의 고정 대상으로 저장하는 방식은 사용하지 않는다.
- 이벤트 처리 시점에도 대상의 생존·활성 상태·사거리·풀 재사용 번호를 확인한다. 기존 대상이 무효라면 기존 탐색 규칙으로 대체 대상을 확인한다. 이벤트 전에 실행한 대상 검사 결과가 계속 유효하다고 가정하지 않는다.
- 유효한 대상이 없으면 화살을 생성하지 않고 공격 모션을 즉시 종료한다.
- 하나의 공격 모션에서 발사는 한 번만 처리한다. 공격 시작이나 발사 순간에 즉시 피해를 주지 않는다.
- 화살 생성 시 목표 참조, 목표의 `ActivationVersion`, 피해량, 발사 위치, 비행 시간을 화살에 전달한다.

### 공격 간격

- **투사체를 발사하는 애니메이션 이벤트를 실행한 시점부터 공격 간격을 계산한다.** 실제로 유효한 대상에게 화살을 발사한 시점을 기준으로 한다.
- 공격 모션 시작 시점이나 애니메이션 종료 시점을 기준으로 계산하지 않는다. 애니메이션 종료 후 공격 간격을 추가로 기다리는 규칙은 폐기한다.
- 공격 간격과 각 화살의 비행 시간은 독립적이다. 화살이 도착할 때까지 기다리는 것을 다음 공격의 조건으로 삼지 않는다.
- 발사 후 목표 변경이나 모션 중도 종료가 발생해도 발사 시점부터 계산하던 대기시간은 유지한다.
- 발사 전에 목표가 없어 모션이 종료됐다면 새 공격 대기시간을 시작하지 않는다. 이전 발사로 생긴 대기시간이 있다면 유지한다.
- 첫 공격에는 이전 발사로 생긴 대기시간이 없다.
- **공격 간격이 끝나도 현재 공격 모션을 끊지 않는다. 현재 모션 종료와 발사 후 공격 간격 경과가 모두 충족되고 유효한 목표가 있으면 다음 공격을 시작한다.**
- 모션이 먼저 끝나면 남은 대기시간만 기다린다. 대기시간이 먼저 끝나면 모션이 끝난 뒤 다음 공격을 시작한다. 모션 종료 시 대기시간을 다시 계산하지 않는다.

### 화살의 이동과 명중

- 화살은 발사 당시 받은 목표를 독립적으로 기억한다. 이후 아군의 현재 대상이 바뀌거나 아군의 공격 모션이 종료돼도 이미 발사한 화살의 목표는 바뀌지 않는다.
- **발사 후 목표가 아군의 사거리를 벗어나도 계속 추적한다.** 비행 중에는 사거리를 취소 조건으로 검사하지 않는다.
- 발사 위치는 발사 순간의 위치로 고정한다. 매 프레임 경과 시간과 비행 시간으로 진행률을 계산하고, 고정된 발사 위치에서 목표의 현재 위치까지 보간한다.
- 진행률이 100%에 도달하는 프레임에 목표의 현재 위치에 도착시킨다. 목표의 이동 속도에 따라 도착이 계속 지연되는 고정 속도 추적 방식은 사용하지 않는다.
- 이동 및 최종 명중 처리 전에 목표가 존재하고 활성 상태이며 체력이 남아 있는지, 저장한 `ActivationVersion`이 일치하는지 확인한다.
- **목표가 먼저 죽거나 경로 끝에 도착해 풀로 반환되면 화살을 종료한다.** 같은 오브젝트가 새 적으로 재사용돼도 기존 화살이 추적하거나 피해를 주면 안 된다. 다른 적으로 화살의 목표를 바꾸지 않는다.
- 목표가 유효한 상태로 비행 시간이 끝나면 저장한 피해량을 목표의 기존 `Enemy.TakeDamage`에 전달한다. 명중 조건은 비행 시간의 완료이며, Collider 충돌 이벤트에 의존하지 않는다.
- 피해는 화살 한 발당 한 번만 적용하고 화살을 종료한다. 풀링 여부는 구현 선택이며, 종료가 반드시 오브젝트 파괴를 뜻하지는 않는다.
- 화살의 비행 시간은 **게임 시간**을 따른다. 게임 배속에 따라 이동이 빨라지거나 느려지고, 게임 일시정지 중에는 비행 시간의 진행과 이동이 멈춘다.

### 구현 연결과 초기 설정

- [Ally.cs](../Assets/Scripts/Ally/Ally.cs): 모든 아군의 모션 시작·취소·진행률 유지 방향 전환·모션 종료 대기·이벤트 시점 대기시간 계산을 담당한다. `ApplyAttack`은 개·걸·윷의 타격 이벤트 수신 함수다.
- [ProjectileAttack.cs](../Assets/Scripts/Ally/ProjectileAttack.cs): 독립 컴포넌트로 투사체 프리팹과 비행 시간을 보관하고, 전달받은 목표·피해량으로 투사체를 생성한다. 대상 탐색과 공격 간격 계산은 하지 않는다. 기존 투사체 공격용 중간 상속 클래스는 제거했다.
- 도·모의 이벤트 수신 함수 → `Ally.ReleaseProjectile`의 대상 확인·단일 공격·공격 간격 처리 → `ProjectileAttack.Fire`의 투사체 생성 순서다. `ProjectileAttack`이 비활성 상태이거나 투사체 참조가 없으면 공격을 시작하지 않으며 발사도 하지 않는다.
- [Mo_Archer.cs](../Assets/Scripts/Ally/Mo_Archer.cs)의 `ReleaseArrow`, [Do_Taoist.cs](../Assets/Scripts/Ally/Do_Taoist.cs)의 `ReleaseMagic`이 각 아군 좌우 클립의 Animation Event 수신 함수다.
- [HomingProjectile.cs](../Assets/Scripts/Ally/HomingProjectile.cs): 발사 시 전달받은 목표 및 재사용 번호를 저장하고, 게임 시간 기준으로 추적·도착 피해·무효 목표에 대한 종료를 처리한다. 현재는 생성 후 종료 시 비활성화·파괴하며 풀링하지 않는다.
- [Mo_Archer 프리팹](../Assets/Prefabs/Mo_Archer.prefab)의 **Projectile Attack 컴포넌트**의 `Projectile Prefab`에 [Mo_Arrow 프리팹](../Assets/Prefabs/Mo_Arrow.prefab)을 연결했다. 코드와 저장 필드 이름은 `projectilePrefab`이며 이전 이름 변환 속성은 없다.
- [Do_Taoist 프리팹](../Assets/Prefabs/Do_Taoist.prefab)의 **Projectile Attack 컴포넌트**의 `Projectile Prefab`에 [Do_Magic 프리팹](../Assets/Prefabs/Do_Magic.prefab)을 연결했다. `ThrowYut` 씬의 소환 설정이 도·모 각각의 프리팹을 참조하는 것을 확인했다.

## 새 공격 구현 시 확인할 동작

아래는 규칙별 확인 목록이다. 위 자동 검증 결과와 화면에서 추가 확인할 범위를 함께 참조한다.

1. 공격 모션 시작 시 체력이 감소하지 않고, 발사 이벤트에서만 화살이 생성된다.
2. 모션 도중 대상 A에서 B로 교체돼도 모션이 이어지고, 발사 이벤트 시점의 B에게 발사한다.
3. 대체 대상이 없으면 모션이 즉시 종료된다. 발사 전 취소는 새 대기시간을 만들지 않고, 발사 후 취소는 기존 대기시간을 유지한다.
4. 화살의 목표가 사거리 밖으로 이동하거나 방향을 바꿔도 정해진 비행 시간에 도착하고 피해가 한 번만 적용된다.
5. 아군이 다른 대상을 선택하거나 모션을 종료해도 이미 발사한 화살은 원래 목표를 추적한다.
6. 목표 사망·경로 도착·풀 반환 시 화살이 종료되며, 풀에서 재사용된 적은 이전 화살의 피해를 받지 않는다.
7. 다음 공격의 대기시간이 애니메이션 시작·종료·명중이 아닌 실제 발사 이벤트 시점에 맞춰 계산된다.
8. 화살이 아군 중심에서 적 중심으로 이동하며 원본 크기를 유지하고, 발사 시점과 비행 중 목표의 현재 위치를 바라보도록 회전한다. 일시정지 중에는 회전도 멈춘다.
9. 공격 간격이 모션보다 먼저 끝나도 모션을 끊지 않고, 모션이 먼저 끝나면 남은 대기시간만 기다린다. 두 조건을 충족했을 때 유효한 목표가 있으면 다음 공격을 시작한다.
10. 목표의 좌우가 바뀌면 공격 진행률을 유지하며 방향을 전환하고, 발사 이벤트가 누락되거나 중복 실행되지 않는다.
11. 게임 배속에 맞춰 화살의 이동 시간이 변하고, 일시정지하면 비행 시간과 위치가 유지된다.

## 기존 구현의 검증 기록

기존 문서에는 Unity 배치 실행에서 첫 타격의 체력 감소, 대기 중 체력 유지, 다음 타격, 처치 후 대상 해제와 대상 변경 시 공격 대기시간 유지를 확인한 기록이 있다. 이는 기존 즉시 피해 구현에 대한 기록이며, 새 투사체 규칙을 검증한 결과가 아니다. 탐색 방식의 비교는 [프로파일링 기록](Profiling/AllyTargetSearch.md)에 남겼다.
