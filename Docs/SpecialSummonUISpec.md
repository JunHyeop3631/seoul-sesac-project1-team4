# 특별재화 HUD와 특별소환창

작업28 완료(2026-11-19): 랜덤 버튼을 작업27 실행기에 연결했다. 재화/공간 부족이어도 창을 열고 실행만 차단하며 부족 이유를 표시한다. 성공 후 자동으로 닫고45→15를 두 숫자에 반영한다. 상단 버튼은 기존 배치 비율을 유지하고 PNG 투명 여백을 보정해 일반재화 HUD와 같은 가시 외곽 너비200으로 맞췄다. 아래 작업27 인용은 당시 기록이다.

작업27 갱신(2026-11-19): 실제 후보 추첨/특별재화30 결제/시작 Cell01의 인구3 재검사/백호 생성과 재입력 보호는 [실행 명세](SpecialSummonSpec.md)에 연결했다.474개 검사에서45→15의 기존 HUD/창 숫자 동기화까지 확인했다. 아래 ‘차감·생성 후속’은 최초 UI 구현 시점 기록이다. 랜덤 버튼 클릭·활성 상태·공간 부족 안내·성공 자동 닫기는 작업28에서 연결하므로 버튼은 현재 비활성으로 유지한다.

## 이번 연결 범위

- 준비 화면 상단 특별재화 버튼을 누르면 확정된 특별소환창이 열린다. 재화가 0이어도 열 수 있다.
- X 버튼으로 닫는다. Esc 단축키는 사용하지 않는다. 열린 동안 뒤쪽 게임판·버튼 입력을 가리며, 닫으면 준비 화면 조작으로 돌아간다.
- 전투 시작·승리·패배·시간 정지 시 창을 닫고 상단 버튼을 비활성화한다. 창을 열고 닫는 동작 자체는 게임 시간 배율을 바꾸지 않는다.
- 기존 `ButtonSound` / `HoverSound`를 재사용한다. 배경음, 윷 결과음, 기존 버튼의 이벤트와 음량은 유지한다.

## 화면 배치

- 기준 해상도는 기존 Canvas와 같은 1920×1080이다.
- 일반 재화와 하트·배속 창의 Rect 크기는 200×75.1이다. 일반 재화 프레임은 원본 PNG를 그대로 복사해 9분할 설정만 추가했으며, 동전 영역과 테두리 모양을 보존한다.
- 상단 특별재화 버튼의 좌측 상단 기준 (266,48),기존 로컬 Rect232×118의 비율을 유지한다. 원본640×288 이미지 좌우16픽셀 투명 여백을 제외한608/640 비율에 맞춰 균등 배율 `200/(232×0.95)`를 적용해 보이는 외곽 너비를200으로 맞춘다. 보라색 버튼 안의 제목과 화살표는 원본 이미지에 포함되어 있다.
- 상단 특별소환 버튼의 클릭 영역은 Image의 alphaHitTestMinimumThreshold 0.1로 보이는 외곽에 맞춘다. 투명 여백과 둥근 모서리 바깥은 클릭되지 않는다. Normal/Hover/Pressed 이미지에 Read/Write를 켜 픽셀 알파 판정을 지원하며 기존 크기와 위치는 유지한다.
- 특별재화 아이콘은 아래 행 왼쪽에 두고, 잔액 숫자는 버튼의 가로 중앙에 정렬한다. 자릿수가 늘어나도 중심을 유지하며 표시 영역 안에 맞춘다.
- 소환창은 화면 중앙의 1120×700 크기다. 제공한 1600×1000 레이아웃을 70%로 배치한다. 첫 적용본보다 12.5% 작게 조정했다.
- 물음표 카드, 제목, 필요 인구 3, 한 줄의 보유·소모 표시, 랜덤 소환, 시작 칸 안내를 원본 투명 PNG로 조립한다. 비용 표시는 30이다.
- 상단/닫기/랜덤 소환의 기존 Normal/Hover/Pressed/Disabled 이미지를 사용한다. 버튼 상태가 바뀌어도 크기·위치·배율을 유지한다. 닫기↔실행 버튼 사이 명시적 탐색을 사용하며 실행 불가일 때는 닫기로 포커스를 돌린다.
- 부족 안내는 하단의 기존 ‘시작 칸에 소환됩니다’ 자리에 표시한다. 공간이 부족하면 ‘시작 칸 공간이 부족합니다. (필요 인구3)’,재화가 부족하면 ‘특별재화가 부족합니다. (필요30)’를 표시한다. 둘 다 부족하면 공간 안내를 우선한다. 조건 회복 시 기존 시작 칸 안내를 복원한다. 글자는 기존 YiSunShin-Bold 폰트와 어두운 갈색을 사용한다.

## 재화와 다음 연결 지점

- 작업08부터 실제 씬의 `SpecialCurrency`는 같은 오브젝트의 `StageCurrency.SpecialBalance`를 읽고 변경 알림을 전달하는 HUD 호환 계층이다. 일반재화와는 분리하되 특별재화 잔액을 둘로 중복 보관하지 않는다. 시작값0·웨이브 이월·씬 재시작 초기화는StageCurrency를 따른다. StageCurrency 없이 단독으로 사용하는 미리보기 객체의 기존 잔액 동작은 유지한다.
- `Grant(int)`로 지급된 값은 `Changed` 이벤트를 통해 HUD와 창 안의 보유량에 동시에 반영된다. 음수 지급은 무시하고 정수 상한을 넘지 않는다.
- 작업08에서 일반 유닛의 완주 보상,작업27에서 후보/결제/배치를 연결했고 작업28은 랜덤 버튼의 실제 클릭을 연결했다. 실행 가능 여부는 매 프레임 및 잔액 변경 시 갱신하고,클릭 순간 실행기가 다시 검사한다. 닫힌 창의 늦은 클릭은 무시하며 성공 알림에서 자동 닫는다. 아이템 지급은 해당 후속 작업에 남긴다.
- 준비 상태·특별재화30·시작 칸 여유 인구3을 모두 만족할 때만 랜덤 버튼을 활성화한다. 창 열기 자체는 재화/공간 조건으로 막지 않는다. 전투/일시정지/던지기/승패 상태에서는 창을 닫고 진입을 막되 HUD 잔액은 유지한다.
- 모달은 뒤쪽 포인터 입력을 가리고,TurnController.LateUpdate는 창이 열려 있으면 보드 클릭/우클릭/Esc 취소 처리를 건너뛴다. 따라서 Esc가 뒤쪽 이동 결과를 취소하거나 소환창을 닫지 않는다. 창을 닫아도 보유 윷 결과·유닛·일반 잔액·배속은 유지한다.

## Unity 연결과 검사

- `Canvas/Special Summon UI`는 `Assets/Prefabs/SpecialSummonUI.prefab` 인스턴스다. 씬에서 TurnController, WaveManager, SpecialCurrency, 기존 두 효과음을 참조한다.
- `Assets/Art/SpecialSummon`: 승인된 이미지 30장과 원본 동전 프레임의 9분할용 복사본 1장. 새 폰트·외부 라이브러리 없음.
- `SpecialSummonUIBuilder.Build`: 프리팹 재생성. `Install`은 초기 연결용이며 이미 연결된 씬에는 중복 설치하지 않는다.
- `SpecialSummonUIBuilder.Complete`는 기존 프리팹의 파일ID와 씬 오버라이드를 보존하며 작업28의 배율/안내/참조를 갱신한다. `CompleteAndRun`은 검증용 복사본에서 프리팹 갱신 후 실제 검사를 실행한다. 기존 `SpecialSummonVerification`은 최초 열기·닫기 단계의 과거 검사로 현재 실행 가능 상태를 판정하는 도구가 아니다.
- 최신 도구는 [SpecialSummonWindowVerification](../Assets/Editor/SpecialSummonWindowVerification.cs)이며 실제 씬 Play Mode에서43개 검사 통과·검사 구간 런타임 오류0이다. [결과](Verification/SpecialSummonWindowVerification.json). 재화0/15 진입,45→15 실제 버튼 클릭/백호1기 생성/자동 닫기,공간4 거부→3 허용,백호2기 뒤 세 번째 차단,중복 콜백,모달 포인터/Esc/포커스,정지/전투/승패/던지기 차단,버튼 호버/누름 이미지와 크기 고정,기존 오디오 수를 확인했다.
- Direct3D11/1920×1080 실제 렌더링: [상단HUD](Previews/SpecialSummonHUD.png)·[실행 가능](Previews/SpecialSummonReady.png)·[재화 부족](Previews/SpecialSummonInsufficient.png)·[공간 부족](Previews/SpecialSummonNoSpace.png)·[버튼 누름](Previews/SpecialSummonPressed.png). 첫 렌더링에서 부족 안내가 하단 테두리에 겹쳐 기존 안내 자리로 옮긴 뒤 다시 검사/렌더링했다. 전체 빌드/수동 완주는 실행하지 않았다.
- 작업27 실행기474개·기존 준비 입력53개 회귀도 통과·각 검사 구간 오류0이다. [회귀 결과](Verification/SpecialSummonWindowRegressionVerification.json). 변경 런타임/프리팹/씬/생성기/검증 코드8개 파일과 검증 복사본의 SHA-256 일치,변경 문서 로컬 링크 및 `git diff --check`를 확인했다.

Game 뷰에서는 상단 특별소환을 열어 재화0에서도 진입/실행 불가 안내를 확인한다. 특별재화45를 확보한 상태에서 랜덤 소환하면15와 백호1기가 남고 창이 닫혀야 한다. 시작 칸에 일반4기가 있으면 공간 부족 안내가 나오며,3기로 줄이면 실행 가능해진다. 전투·일시정지 중에는 상단 잔액만 유지하고 클릭으로 열리지 않아야 한다.
