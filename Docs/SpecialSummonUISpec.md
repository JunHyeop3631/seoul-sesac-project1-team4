# 특별재화 HUD와 특별소환창

## 이번 연결 범위

- 준비 화면 상단 특별재화 버튼을 누르면 확정된 특별소환창이 열린다. 재화가 0이어도 열 수 있다.
- X 버튼으로 닫는다. Esc 단축키는 사용하지 않는다. 열린 동안 뒤쪽 게임판·버튼 입력을 가리며, 닫으면 준비 화면 조작으로 돌아간다.
- 전투 시작·승리·패배·시간 정지 시 창을 닫고 상단 버튼을 비활성화한다. 창을 열고 닫는 동작 자체는 게임 시간 배율을 바꾸지 않는다.
- 기존 `ButtonSound` / `HoverSound`를 재사용한다. 배경음, 윷 결과음, 기존 버튼의 이벤트와 음량은 유지한다.

## 화면 배치

- 기준 해상도는 기존 Canvas와 같은 1920×1080이다.
- 일반 재화와 하트·배속 창의 Rect 크기는 200×75.1이다. 일반 재화 프레임은 원본 PNG를 그대로 복사해 9분할 설정만 추가했으며, 동전 영역과 테두리 모양을 보존한다.
- 상단 특별재화 버튼은 좌측 상단 기준 (266, 48), 232×118이다. 보라색 버튼 안의 제목과 화살표는 원본 이미지에 포함되어 있다.
- 특별재화 아이콘은 아래 행 왼쪽에 두고, 잔액 숫자는 버튼의 가로 중앙에 정렬한다. 자릿수가 늘어나도 중심을 유지하며 표시 영역 안에 맞춘다.
- 소환창은 화면 중앙의 1120×700 크기다. 제공한 1600×1000 레이아웃을 70%로 배치한다. 첫 적용본보다 12.5% 작게 조정했다.
- 물음표 카드, 제목, 필요 인구 3, 한 줄의 보유·소모 표시, 랜덤 소환, 시작 칸 안내를 원본 투명 PNG로 조립한다. 비용 표시는 30이다.
- 상단 버튼 Normal/Hover/Pressed, 닫기 Normal/Pressed, 랜덤 소환 Disabled 이미지를 연결한다. 버튼 상태가 바뀌어도 크기·위치는 유지한다.

## 재화와 다음 연결 지점

- `SpecialCurrency`는 일반 재화와 분리된 씬 단위 잔액이다. 시작값 0, 다음 웨이브 이월, 씬 재시작 시 초기화를 따른다.
- `Grant(int)`로 지급된 값은 `Changed` 이벤트를 통해 HUD와 창 안의 보유량에 동시에 반영된다. 음수 지급은 무시하고 정수 상한을 넘지 않는다.
- 이번 요청은 UI 열기·닫기까지다. 완주 보상·아이템 지급, 30 차감, 시작 칸 인구 검사, 후보 추첨, 유닛 생성은 아직 연결하지 않았다.
- 실제 소환 처리가 없는 상태에서 동작하지 않는 버튼을 활성화하지 않도록, 현재 랜덤 소환 버튼은 비활성으로 유지한다. 충분한 재화만으로 활성화하지 않는다.

## Unity 연결과 검사

- `Canvas/Special Summon UI`는 `Assets/Prefabs/SpecialSummonUI.prefab` 인스턴스다. 씬에서 TurnController, WaveManager, SpecialCurrency, 기존 두 효과음을 참조한다.
- `Assets/Art/SpecialSummon`: 승인된 이미지 30장과 원본 동전 프레임의 9분할용 복사본 1장. 새 폰트·외부 라이브러리 없음.
- `SpecialSummonUIBuilder.Build`: 프리팹 재생성. `Install`은 초기 연결용이며 이미 연결된 씬에는 중복 설치하지 않는다.
- `SpecialSummonVerification.Run`은 **별도 프로젝트 복사본**에서만 실행한다. 검사 완료 시 Unity 프로세스를 종료한다.
- 재화 0에서 열기, 표시 동기화, 차감·생성 없음, 모달 입력 차단, 닫기, 전투·일시정지 차단, 다음 준비 단계 복귀, 버튼 눌림 크기 유지, 기존 오디오 개수를 검사한다.
