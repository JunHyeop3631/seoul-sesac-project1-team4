# 일반 완료 보상 두루마리 — 작업43

기존 완료 표시를 작업22/39의 실제 지급액에 연결해 일반60·천명전120을 표시한다. 정산/다음 준비는 즉시 진행하고 두루마리는 표시만 하며 재화를 다시 지급하지 않는다. 중앙부터 양끝으로0.4초 펼침·1.5초 유지·0.3초 사라짐,UI 시간은1/2/4배속에 무관한 실제 시간이다. 펼침 뒤 완료 문구·코인/실제 지급액을 표시하고 모든 그래픽/그룹은 준비 입력을 막지 않는다.

기존 WaveCompleteHUD/Banner·13개 아트·보드 위 가로 발판 위치를 유지한다. 실제 일반 완료와 천명전 완료,실제 지급액 경계·준비 조작·새 전투/승패 숨김을 검증한다. 최종 보스/하트0 패배에는 일반 완료 두루마리를 표시하지 않으며,늦은 완료 알림이 결과 뒤에 도착해도 표시하지 않는다. 결과 화면44~45와 전체 점검46은 후속이다.

## 실행 흐름과 변경

`TurnController.EndBattle`의 기존 정산 → 다음 준비 → `WaveCleared(완료 번호, 실제 지급액)` → `WaveCompleteHUD.Show` → `WaveCompleteBanner.Play` 경로를 사용한다. 지급은 TurnController만 수행하고 Banner는 전달받은 값을 표시한다. 기존 13개 프레임·프리팹·위치·레이아웃·연출 시간은 유지했다.

`WaveCompleteHUD.Show`에 활성 상태·컨트롤러 참조·최종 승패 검사를 추가했다. 준비 전환 콜백에서 이미 패배한 뒤 남은 완료 신호가 전달되면 기존 Hide 이후 다시 Play되는 문제가 있었다. 검증 콜백으로 이 순서를 재현해 수정 전 첫 검사 실패를 확인했고, 수정 후 최종 결과를 유지한다. 일반 플레이에서 이 콜백이 자연 발생한다고 주장하는 것은 아니다.

`WaveCompleteBanner.Update`는 기존 `Time.unscaledDeltaTime`으로 펼침0.4초, 유지1.5초, 페이드0.3초를 처리한다. 글자는 펼침 뒤 표시하고 프레임 이미지를 교체해 가로로 늘리지 않는다. 그래픽 raycast·CanvasGroup 입력을 끄므로 준비 입력을 가로막지 않는다. 새 전투/승패/비활성화에서는 즉시 숨긴다.

## 작업43 검증 (2026-11-19)

별도 Unity 6000.3.28f1 프로젝트의 실제 ThrowYut 씬 Play Mode에서 [1468개 검사](Verification/WaveCompleteRewardVerification.json) 통과, 검사 구간 오류0이다. 검사 수에는 프레임별 단조 증가 확인이 포함돼 실행 속도에 따라 달라질 수 있다.

| 배속 | 실제 완료 지급 | 펼침 완료 | 페이드 시작 | 숨김 완료 |
| --- | --- | --- | --- | --- |
| 1 | 60 | 0.4001초 | 1.9003초 | 2.2000초 |
| 4 | 120 | 0.4000초 | 1.9005초 | 2.2000초 |

- 천명전·부적을 실제 구매/사용하고 게임 배속 버튼으로4배속을 설정했다. 다음 준비에서도 실제 지급액과 완료한 웨이브1 표시를 확인했다.
- 연출 중 상점 버튼·인벤토리·실제 유닛 소환/진화/이동·윷 던지기 실행 및 비용1회 차감을 확인했다. UI 연출 단계나 표시 재호출은 재화를 지급하지 않는다.
- 정수 상한 직전 완료에서는 실제 증가량17을 `+17`로 표시했다. 잘못된 번호 입력·비활성화·다음 전투·최종 보스 처치·패배 뒤 늦은 알림·새 씬 초기 숨김을 확인했다.
- 13개 PNG의 알파 영역 폭은64→984픽셀로 단조 증가하며 중심이 고정된다. 1920×1080 렌더링에서 [일반60](Previews/WaveComplete60.png)·[천명전120](Previews/WaveComplete120.png)·[펼침 중](Previews/WaveCompleteUnfold.png)·[페이드](Previews/WaveCompleteFade.png)를 확인했다. 펼침 중 캡처는 보상 없는 표시 재호출로 촬영했다.

빠른 완료를 위해 검증 중 메모리의 첫 웨이브를 적1기로 교체하고 치명 피해/사망 완료를 호출했다. 상한 검사는 소유된 적의 도착 콜백, 종료 순서는 검증용 콜백으로 유도했다. 데이터·씬에 이 조건을 저장하지 않았다. 전체 한 판 수동 플레이와 새 플레이어 빌드는 수행하지 않았으며 통합 점검은 작업46이다.

기존 [완료 보상88개](Verification/CompletionRewardVerificationAfterWaveCompleteReward.json)·[천명전69개](Verification/HeavenlyMandateVerificationAfterWaveCompleteReward.json) 회귀도 통과했고 검사 구간 오류0이다. 원본과 검증 복사본의 HUD/Banner 코드·검증 도구·프리팹·씬 SHA-256 일치, 문서 링크와 `git diff --check`를 확인했다.

재실행은 별도 프로젝트에서 `-executeMethod WaveCompleteRewardVerification.ReimportAndRun`을 사용한다. 검증 후 에디터를 종료하므로 원본 에디터에서 직접 실행하지 않는다.
