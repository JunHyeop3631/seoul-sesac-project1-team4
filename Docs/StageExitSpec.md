# 메인 이동·종료 확인 — 작업41

> 2026-11-19 작업42: [실제Windows 플레이어 검증](BuildMainEntrySpec.md)에서 메인 확인 취소/이동·재시작과 Application.Quit 종료0을 확인했다. 아래41의 플레이어 종료 미실행 설명은 당시 범위다.

현행 ImplementationGaps의 작업41/GAP-009·21장 범위 보정과 ResultFlagUISpec의 결과2버튼 규칙을 기준으로 구현한다. 진행 중 메인/종료에는 진행 소멸 확인을 제공하고,취소하면 진행·열린 UI·선택·배속을 보존한다. 확인 전 초기화/씬 이동/종료는 없다. 확인 후 메인은 Title로 이동해 진행 씬을 폐기하고 새 게임은120/0·하트10·1웨이브다. 종료는 프로세스 종료로 중간 진행을 저장하지 않는다.

결과창 메인/재도전은 기존 확정 버튼 경로를 유지하고 추가 종료 버튼을 넣지 않는다. 타이틀 종료는17장에 확인 요구가 없어 기존 즉시 종료를 유지한다. 필수 진행 중 나가기 진입을 작은 메인/종료 HUD 버튼으로 제공한다. 일반 ESC 일시정지/계속하기 메뉴 OPT-002는 채택하지 않으며 이번 ESC는 열린 확인창 취소만 담당한다.

확인창은 시뮬레이션을0배속으로 보류하고 확인 직전 배속/포커스를 저장한다. 취소 시 복원하고 기존 준비 창/정보/사거리는 확인 대기 동안 닫거나 전환하지 않는다. 동작은 배경 모달로 차단하고 공개 게임 실행 경로는 기존 시간/처리 잠금 검사를 유지한다. 실제 종료는 에디터 Play Mode 종료 분기와 플레이어 Application.Quit 분기를 구분해 검증한다.

## 실행 흐름

1. [StageExitConfirmation](../Assets/Scripts/UI/StageExitConfirmation.cs)의 진행 중 메인/종료 HUD 버튼이 RequestHome/RequestQuit를 호출한다. 처리 중 소환/이동/아이템/구매와 재화 알림 중에는 요청을 받지 않는다. 열린 확인을 다른 요청으로 덮어쓰지 않는다.
2. Open은 배속·EventSystem 포커스를 저장하고 IsOpen을 먼저 켠 뒤 Time.timeScale=0으로 시뮬레이션을 보류한다. 전체 화면 레이캐스트 배경과 취소/확인 버튼을 표시한다. 취소가 기본 선택이며 열린 확인창의 Esc도 Cancel로 연결한다.
3. [TurnController.IsExitConfirmationOpen](../Assets/Scripts/Turn/TurnController.cs)을 기존 정보/사거리/행동 버튼/상점/인벤토리/특별소환 창의 갱신 경로에서 확인한다. 확인 대기 중에는0배속을 이유로 창·선택을 닫거나 정보 전환을 진행하지 않는다. 게임 실행 가능 조건은 기존0배속 제한을 유지한다. GameSpeedButton도0배속의 강제 클릭을 무시한다.
4. Cancel은 저장한 배속/포커스를 복원하고 확인창만 닫는다. Confirm은1회 잠금 후 메인 이동이면1배속으로 Title을 로드해 진행 씬을 폐기한다. 종료면 에디터에서는 Play Mode를 종료하고 플레이어에서는 Application.Quit를 호출한다. 확인 뒤와 폐기된 컨트롤러의 늦은 콜백은 다시 실행하지 않는다.
5. 결과가 늦게 확정되는 경우 확인창을 닫고 결과창의0배속을 유지한다. 기존 ResultFlagView의 결과 메인 버튼은 준비/중복 입력 보호와0.08초 눌림 후 직접 Title로 이동하는 확정 버튼 정책을 유지한다. 결과창에 별도 종료 버튼을 추가하지 않았다.
6. [StageCurrency.Notify](../Assets/Scripts/Turn/StageCurrency.cs)는 기존 Changed/SpecialChanged 알림 동안 읽기 전용 IsNotifying를 제공한다. 중첩 알림은 이전 상태를 복원하고 지급액·알림 순서는 유지한다. 확인 요청이 지급 콜백 안에서 씬을 폐기하지 못하게 한다.
7. [StageExitBuilder](../Assets/Editor/StageExitBuilder.cs)는 기존 Canvas의 배속 아래에 작은 메인/종료 진입과 확인창을 연결한다. 기존 설명 프레임 이미지를 원래 비율로 재사용하고 제목/본문/버튼을 보이는 테두리 안에 배치한다. 기존 HUD·아이템 창의 위치/크기를 바꾸지 않는다. 저장 후 재로드해 주요 참조를 검사한다.
