# 작업18 근접 공격 표적 유지 대조 (2026-11-18)

판정: **전사·창병의 진행 중 공격은 시작 표적을 보장하지 않는다. GAP-031은 미해결로 유지한다.** 작업18의 대조는 완료했고 런타임 코드·프리팹·씬은 수정하지 않았다.

## 비교 기준

작업12에서 다시 내보낸 사용자 지정 Google Docs 탭4의10장 기준은 개 전사·양 창병이 공격 시작 때 선택한 표적을 타격까지 유지하는 것이다. 생존한 원래 표적은 타격 전에 사거리를 벗어나도 예정 피해를 받고,사망·탈출이면 피해 없이 동작을 마치며 진행 중 공격의 피해를 다른 적에게 옮기지 않는다. 기존 공격 간격과 남은 대기시간은 유지한다. 같은 장의 개발 완료 전달 및 추가 구현 지시 중단 조건에 따라 관찰·기록하는 범위다.

## 실행 경로

`Ally.LateUpdate`가 매 프레임 RefreshTarget을 실행한다. 현재 표적이 사거리 밖/사망/비활성화이면 Wave.FindAttackTarget으로 다른 유효 표적을 찾는다. 찾으면 진행 공격을 유지하고,없으면 OnTargetUnavailable이 공격을 취소해 Idle로 돌아간다.

실제 공격 클립의 `ApplyAttack` 이벤트는 `AllyAnimationEvents→Ally.ApplyAttack→TryBeginAttackEvent→RefreshTarget`을 거쳐 **그 시점의 CurrentTarget**에 피해를 준다. 별도의 공격 시작 표적을 보관하지 않으므로 원래 표적을 잃었을 때 진행 중 피해가 대체 표적으로 옮겨질 수 있다. released 플래그와 nextAttackTime은 기존 공격에 남는다. 이번 작업은 이 경로를 바꾸지 않았다.

## 검증 배치와 한계

[MeleeTargetVerification.cs](../Assets/Editor/MeleeTargetVerification.cs)는 실제 씬의 Wave/EnemyPool/AllyPool과 네 프리팹의 실제 Animator·클립·Animation Event를 사용한다. Ally의 ApplyAttack이나 UpdateAttack을 직접 호출하지 않고 모션 시작 직후 표적 조건을 바꿔 실제 피해·취소·공격 기한을 관찰한다.

- 일반 적2기/HP10000 배치를 실행하고 위치를 정해 첫 표적과 대체 표적을 구분한다. 원래 표적은0.3거리,대체 표적은 사거리 내/외에 두며 방향을 좌우로 반복한다.
- 거리는 실제 Transform을 바꿔 Physics2D에 동기화하고,사망은 공개 TakeDamage를 사용한다. 탈출은 이동 정지 전 보관한 실제 Wave 도착 콜백을 직접 호출해 탈출/풀 반환 상태로 만든다. 전체 경로 완주 시간을 재검증한 것은 아니다.
- TurnController와 처치 보상 UI는 메모리에서만 비활성화해 턴 진행/승패/보상을 이 표적 대조에서 분리한다. 게임 시간은 captureDeltaTime=.01로 고정한다. 상태 변경 시점은 실제 플레이의 빈도나 난이도 측정이 아니다.
- 검사 중의 데이터/위치/시간/컴포넌트 설정은 저장하지 않았다. 검증한 런타임·프리팹·씬·검증 도구의 SHA-256이 작업본과 일치한다. 원본 에디터는 유지하고 기존 검증 복사본/캐시를 재사용했다.

전체 빌드·모션 화면 렌더링·철퇴병 범위 피해·원거리 투사체 판정은 이번 범위가 아니다. 초기 에디터 검색 인덱스 예외는 검사 시작 전의 로그이며 오류0은 검사 구간 기준이다.

재실행은 별도 검증 복사본에서 배치 `-executeMethod MeleeTargetVerification.ReimportAndRun -nographics`를 사용한다. Logs/MeleeTargetVerification.json에 결과를 쓰고 검증 편집기를 종료하므로 원본의 열린 에디터에서 직접 실행하지 않는다.
