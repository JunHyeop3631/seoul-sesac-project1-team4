# 작업20 투사체 이동과 소멸 대조 (2026-11-18)

판정: **동일 일정 속도 이동(GAP-029)과 공격자 사거리 이탈 시 소멸(GAP-030)은 미충족이다.** 대조 작업은 완료했으며 런타임 코드·프리팹·씬은 수정하지 않았다. 새로운 투사체 속도 값을 제안하거나 확정하지 않는다.

## 기준과 실행 결과

작업12에서 다시 내보낸 사용자 지정 Google Docs 탭4의10장 기준은 도사의 마법탄과 궁수의 화살이 같은 일정 속도로 현재 표적을 추적하고,거리에 따라 비행 시간이 달라지는 것이다. 발사 후에도 표적이 죽거나 탈출하거나 공격자 중심 사거리 밖이면 즉시 소멸·무피해이며 다른 적으로 재표적하지 않는다. 같은 장의 개발 완료 전달/추가 구현 지시 중단 조건에 따라 현재 구현을 대조했다.

Unity6000.3.28f1 ThrowYut 씬 복사본에서 도사/궁수1·2성4개 프리팹×13상황=52개를 관찰했다. 관찰 검사348개 통과·검사 구간 런타임 오류0. [결과 JSON](Verification/ProjectileBehaviorVerification.json)의 checksPassed=true는 관찰 검사가 통과했다는 뜻이며,constantSpeedRequirementSatisfied와 attackerRangeRequirementSatisfied는 모두 false다.

## 속도와 도착 시간

| 실제 발사체 | 가까운 정지 표적의 속도 | 먼 정지 표적의 속도 | 두 경우 종료 관찰 시간 | 연속 이동 표적의 표본 속도 |
| --- | ---: | ---: | ---: | ---: |
| 도사1·2성 | 약3.371 | 약10.012 | 모두 약0.31게임초 | 약3.371~7.215 |
| 궁수1·2성 | 약3.333 | 약10.000 | 모두 약0.31게임초 | 약3.333~7.265 |

속도 단위는 유닛/게임초다. 가까운 표적은 원점에서1유닛,먼 표적은3유닛에 두었다. 실제 발사점은 각 프리팹의 launchCenterRenderer 기준이므로 도사 실거리 약1.011/3.004와 궁수1/3이 조금 다르다. 숫자는 현재 동작의 측정값이며 새 설정값이 아니다.

ProjectileAttack은 flightDuration=.3을 전달하고 HomingProjectile은 발사점과 현재 표적 위치를 elapsed/flightDuration으로 Lerp한다. 따라서 정지 표적의 거리가 길면 더 빠르게 이동해 같은 시간에 도착한다. 연속 이동 표적은 매 게임초 X방향2/Y방향0.5로 이동시켰으며,투사체 속도도 위처럼 달라졌다. 순간 위치 변경 사례도 따로 포함했다.

종료 관찰 시간0.31은 .01초 고정 게임 프레임에서 비활성화를 확인한 시각이다. 설정된.3초 도착과 한 관찰 프레임 이내로 일치한다. 프레임별 이동 속도와 초기 거리/종료 관찰 시간으로 계산한 평균값은 결과JSON에서 별도 필드다. 비행 시간이 거리에 따라 달라지는 일정 속도 요구와 차이가 있다.

대체 표적은 모든 상황에서 피해0이었다. 정상 명중은 도사12/25.2,궁수8/16.8과.01 미만 오차로 일치했고 반환 후 추가 피해도 없었다. 이 검사는 현재 피해 전달·초기화 확인이며 공격 DPS나 애니메이션 발사 주기를 검증한 것은 아니다.

## 확인한 경로와 검증 한계

[ProjectileBehaviorVerification.cs](../Assets/Editor/ProjectileBehaviorVerification.cs)는 실제 네 아군 프리팹의 ProjectileAttack.Fire→실제 ProjectilePool/투사체 prefab→정상 HomingProjectile.LateUpdate를 실행한다. 아군 공격 Animator는 비활성화해 추가 자동 발사를 막는다. 이 검증에서 발사 애니메이션 이벤트를 거치지는 않으며,투사체 갱신 함수를 직접 호출하지도 않는다.

현재 Launch는 표적·피해·비행 시간·효과·Wave만 받으며 발사자/공격 사거리 참조는 없다. LateUpdate는 Wave 실행 상태,표적 활성/체력/ActivationVersion을 검사하고,그 다음 비행을 진행해 마지막에 피해1회와 반환을 처리한다. 이 구조가 사망/탈출/재사용/종료를 처리하지만 공격자 중심 거리는 확인하지 않는다.

검사 중에만 고HP 적2기와 위치 이동/치명 피해/실제 도착 콜백/풀 재사용을 사용했다. Wave와 풀은 실제 씬의 객체이고,턴 진행/처치 보상은 메모리에서 분리했다. captureDeltaTime=.01의 고정 게임 시간이며 벽시계 실험이나 일반 플레이의 발생 빈도가 아니다. 무효화는 비행 중에 주었고 정확히 같은 프레임의 명중/외부 이벤트 순서 경쟁까지 검증한 것은 아니다.2/4배속 별도 측정·전체 빌드·렌더링은 이번 범위가 아니다.

검사 설정은 저장하지 않았고 검증한 런타임·프리팹·씬·검증 도구의 SHA-256이 작업본과 일치한다. 원본 에디터는 유지하고 기존 검증 복사본/캐시를 재사용했다. 초기 검색 인덱스 예외는 검사 시작 전이며 위 오류0은 검사 구간 기준이다.

재실행은 별도 복사본에서 `-executeMethod ProjectileBehaviorVerification.ReimportAndRun -nographics`를 사용한다. Logs/ProjectileBehaviorVerification.json에 결과를 쓰고 검증 편집기를 종료하므로 원본의 열린 에디터에서 직접 실행하지 않는다.
