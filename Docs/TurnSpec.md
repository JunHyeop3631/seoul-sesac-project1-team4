## 확정된 진행 순서

**턴 시작 → 준비 단계（윷 던지기 → 해당 결과로 소환 또는 이동 완료를 선택적으로 반복） → 전투 시작 버튼 → 전투(웨이브) 시작 → 웨이브 하나 방어 → 웨이브 완료 → 하트가 남고 다음 웨이브가 있으면 다음 준비 단계 / 마지막 웨이브면 Victory Panel 표시**

턴은 준비 단계에 앞서 시작하며, 한 턴은 준비 단계와 전투(웨이브)로 구성된다. 윷 던지기와 윷 행동은 턴 안의 준비 단계에서 진행한다. 한 턴에는 웨이브 하나를 방어한다. 플레이어가 전투 시작 버튼을 누르면 준비 단계를 마치고 전투(웨이브)를 시작한다. 중간 웨이브를 마치고 하트가 남으면 자동으로 다음 턴의 준비 단계에 진입한다. 다음 전투는 전투 시작 버튼을 별도로 눌러 시작한다.

웨이브 구성·몬스터 등장·전투 진행·완료 판정 및 관련 클래스의 책임은 [웨이브 명세](WaveSpec.md)에서 다룬다. 이 문서는 턴의 단계 전환과 준비 단계 규칙을 다룬다.

## 턴 규칙 확인 진행 중

링크 기획 문서와 현재 구현을 참고하되, 사용자에게 조건을 확인한 뒤 이 명세에 기록한다. 링크 문서의 제안이나 현재 코드의 동작을 새 확정 규칙으로 간주하지 않는다. 이번 작업은 명세 작성까지이며, 구현은 이후에 진행한다.

참고: [윷놀이 웨이브 디펜스 기획 문서](https://docs.google.com/document/d/1NM-D30vqywVCfJryjdS6B17rJT8bwrZYDl4Uoiu8Ojc/edit)

### 이번 논의에서 확정한 조건

- 한 턴에 웨이브 하나를 방어한다.
- 준비 단계에서는 보유 재화로 윷을 던질 수 있다. 고정된 던지기 횟수는 적용하지 않으며, 재화가 남아 있어도 던지기를 그만두고 전투를 시작할 수 있다.
- 윷 결과는 모아 두지 않는다. 한 번 던진 뒤 해당 결과로 소환 또는 이동을 완료해야 다음 윷을 던질 수 있다.
- 턴 시작 후 준비 단계에 진입한다. 플레이어가 별도의 전투 시작 버튼을 눌러 전투(웨이브)를 시작한다. 윷을 던졌다면 해당 결과로 소환 또는 이동 행동을 완료해야 전투를 시작할 수 있다.
- 윷 던지기와 전투 시작은 별개의 선택이다. 준비 단계에서 윷을 한 번도 던지지 않고 바로 전투를 시작할 수 있으며, 전투 시작에 최소 던지기 횟수를 요구하지 않는다.
- [웨이브의 완료 조건](WaveSpec.md#완료-조건)을 만족하면 전투가 종료된다. 다음 준비 단계 또는 최종 승리로의 전환은 아래 규칙을 따른다.

### 던지기 재화와 비용

- 윷 던지기와 상점 구매에 같은 공용 재화를 사용한다.
- 재화 이름은 미정이다.
- 던지기 1회 비용은 매번 같다. 금액은 미정이며, 이후 임시 값을 지정할 예정이다. 이 명세에서는 임의의 금액을 확정하지 않는다.
- 던지기 버튼을 눌러 실제 던지기가 시작될 때 비용을 차감한다.
- 사용하지 않은 재화는 다음 턴의 준비 단계로 전부 이월된다.
- 게임 시작 시 초기 재화를 지급하며, 몬스터 처치 시 재화를 지급한다. 웨이브 클리어 추가 지급과 매 준비 단계 기본 지급은 적용하지 않는다. 초기 지급량과 처치 보상액은 미정이다.
- 보유 재화가 던지기 1회 비용보다 적으면 던지기를 막는다.
- 몬스터의 기지 도달 처리와 처치 보상 제외 조건은 [웨이브의 전투와 몬스터 이탈](WaveSpec.md#전투와-몬스터-이탈)을 따른다.

### 전투 단계와 상태 유지

- 윷 던지기는 준비 단계에서만 가능하며, 전투 중에는 던질 수 없다.
- 전투 시작 이후 몬스터 등장·전투 진행·완료 판정은 [웨이브 명세](WaveSpec.md)를 따른다.
- 기지 내구도는 다음 턴에도 남은 값 그대로 유지한다.

### 턴 종료와 다음 준비 단계

- 중간 웨이브를 마치고 하트가 남으면 `EndBattle → EndTurn → StartTurn → BeginPreparation` 순으로 다음 준비 단계에 자동 진입한다. 승리 패널은 표시하지 않는다.
- `EndTurn`에서 `currentTurnNumber`를 1 증가시킨다. 다음 준비 단계에서 처치 수를 0으로 초기화하고 `PreparationStarted` 이벤트로 결과 패널을 닫는다.
- 마지막 웨이브는 `WaveManager.waves` 배열의 마지막 항목으로 판정한다. 완료 시 하트가 남으면 `IsBattleWon`을 설정하고 `BattleWon` 이벤트를 보낸다. 최종 승리 후에는 전투 재시작과 다음 웨이브 전환을 막는다.
- 적을 놓쳤더라도 하트가 남으면 동일한 전환 규칙을 적용한다. 하트가 0이면 패배 상태를 유지한다.
- 배치한 아군의 위치·종류·진화 상태를 그대로 유지한 채 다음 준비 단계로 넘어간다.
- 상점은 준비 단계에서만 이용할 수 있다.

### 전투 결과 깃발

- `Heart HUD`는 상단 앵커 `(0.5, 1)`, 중앙 피벗 `(0.5, 0.5)`을 사용한다. 배경 크기는 `200 × 85.3`이며 피벗 변경에 맞춰 Y를 `-96.549995`로 보정해 화면 위치를 유지한다. 하트·×·숫자는 중앙 앵커와 중앙 피벗으로 통일하고 각각 X `-50 / 0 / 50`, 크기 `44 × 39.285713 / 24 × 24 / 56 × 44`로 배치한다. × 표시는 배경의 정중앙에 두고 하트와 숫자의 중심 위치는 좌우 대칭으로 맞춘다.

- 마지막 웨이브가 완료됐고 잔여 하트(`RemainingLives`)가 1 이상이면 `Victory Panel`을 표시한다. 중간 웨이브에서는 표시하지 않는다.
- 잔여 하트가 0이 되는 즉시 `HUD/패배 깃발` 이미지를 표시한다. 이후 하트가 이미 0이면 패배 알림을 반복하지 않는다.
- 경로 끝에 도달해 사라진 적은 처치 수에 포함하지 않는다. 적이 일부 도착했더라도 마지막 [웨이브 완료](WaveSpec.md#완료-조건) 시 하트가 남아 있으면 승리 패널을 표시한다. 전원 처치는 승리 조건이 아니다.
- 패배를 승리보다 우선한다. 하트가 0인 상태에서 웨이브가 완료되어도 승리를 알리거나 다음 턴 시작 흐름을 실행하지 않는다.
- 게임 시작 시 결과 패널은 숨겨진다. 최종 승리 패널은 표시 상태를 유지한다. 하트가 0이거나 최종 승리한 뒤에는 새 전투를 시작할 수 없다.
- `TurnController`가 `PreparationStarted`, `BattleStarted`, `BattleWon`, `BattleLost` 이벤트를 보내고, [BattleStateHUD](../Assets/Scripts/UI/BattleStateHUD.cs)가 이를 받아 전투 시작 안내와 승리·패배 패널을 전환한다.
- [ThrowYut 씬](../Assets/Scenes/ThrowYut.unity)의 `Canvas`에 `BattleStateHUD`를 연결하고 `Start Wave Panel`, `Victory Panel`, `Defeat Panel`을 참조한다. 전투 시작 안내는 전투가 실제로 시작되면 표시되고, 배속에 관계없이 실제 시간 1초 후 숨겨진다. 그 전에 승리·패배 또는 다음 준비 단계로 전환되면 즉시 숨겨진다. 각 패널은 왼쪽 화면 영역을 덮으며 이미지를 자식으로 가진다.
- 다음 턴 버튼 오브젝트와 버튼 참조, 클릭 함수 및 버튼 대기 상태는 제거했다. 다음 준비 단계 전환은 `EndBattle`에서 직접 처리한다.

### 행동 선택과 준비 중 상점 이용

- 던지기 시작부터 결과에 따른 소환·이동 완료까지 `Throw Button`을 숨긴다. 결과가 나오면 결과 아래에 소환·이동 버튼을 표시한다.
- 소환이 성공하면 첫 배치 칸에 유닛을 등록한 뒤 던지기 버튼을 다시 표시한다. 이동은 아군과 도착 칸을 선택하고 실제 이동이 끝나야 결과를 소비한다.
- 이동 선택 중에는 소환 버튼을 어둡게 표시하고 입력을 차단한다. 이동 완료 시 원래 표시로 복원한다.
- 전장에 배치된 아군이 없을 때 백도가 나오면 결과를 소비하고 다시 던질 수 있다. 이미 차감한 던지기 비용은 환급하지 않는다.
- 백도는 실제로 들어온 경로를 되짚어 한 칸 후진한다. 한 번에 여러 칸 이동한 경우 중간 칸까지 기록하며, 연속 백도는 기록을 한 칸씩 되짚는다. 소환 직후 1번 칸에서는 0번 칸으로 돌아간다.

- 윷 던지기 연출이 진행되는 동안에는 상점 열기를 막는다. 결과가 나온 뒤 윷 결과를 사용하는 중에는 상점 이용이 가능하다.
- 소환 또는 이동 버튼을 누르는 순간 해당 윷 결과에 사용할 행동이 확정된다. 완료 전 다른 행동으로 바꿀 수 없다.
- 소환·이동의 완료 시점은 실제 배치 또는 이동이 끝난 시점이다. 행동 선택이나 도착 칸 클릭만으로 완료 처리하지 않는다. 연출이 있다면 실제 배치·이동이 끝날 때까지 다음 던지기와 전투 시작을 막는다.
- 이동을 확정한 뒤에도 다른 아군을 선택하여 도착 후보를 갱신할 수 있다는 기존 [윷 행동의 선택 처리](YutActionSpec.md#선택-처리) 규칙을 유지한다.
- 이동시킬 아군이 하나도 없으면 이동 버튼을 비활성화한다.
- 윷 결과를 아직 사용하는 중에도 상점을 이용할 수 있다. 상점 이용이 가능하더라도 해당 윷 결과로 소환 또는 이동을 완료하기 전에는 다음 던지기 및 전투 시작이 불가능하다.
- 상점 창이 열려 있으면 윷 던지기 및 전투 시작이 불가능하다. 상점 창을 닫은 뒤 각 행동의 나머지 조건을 만족해야 실행할 수 있다.

### 이번 논의에서 제외하는 항목

- 잔여 하트 0에 따른 패배 깃발 표시는 위 규칙으로 확정했다. 재시작·종료 버튼과 패배 후 전체 전투 중단 등의 추가 처리는 이번 변경 범위에서 다루지 않는다.
- 일반 진화와 특별진화는 턴 흐름 명세에서 제외한다. 진화 승인이나 특별진화 처리를 턴 전환의 필수 조건으로 추가하지 않는다.
- 링크 문서의 목표지점 도착은 아군이 목표에 도착한 뒤 다음 윷 던지기로 특별진화한다는 구상이다. 현재 로컬 명세에서 완주 규칙은 미정이며, 이번 턴 논의에서 해당 구상을 확정하거나 턴 흐름에 포함하지 않는다.

### 확인할 항목

- 스테이지와 턴·웨이브의 관계, 준비 단계의 재화·던지기 비용·종료 조건.
- 던지기와 결과 소비, 재던지기·추가 던지기, 입력 허용 시점.
- 소환·이동의 완료와 실패, 선택 변경·취소, 행동 불가 상황.
- 칸 수용량과 교체는 기존 명세에서 후속 구현 대상으로 둔 범위를 참고한다. 진화·목표 도착·특별진화는 이번 턴 흐름 확인 대상에서 제외한다.
- 턴 진행에 필요한 전투 상태 전환과 웨이브 시작·완료 알림 연결.
- 턴 종료 정산, 상점·보상, 다음 준비 단계 진입.
- 전투 중 가능한 조작, 상태 표시, 일시정지·배속, 최종 웨이브 이후 처리.

## 현재 구현

1. [YutThrowController](../Assets/Scripts/Yut/YutThrowController.cs)가 윷 결과 이미지를 표시하고 `ThrowCompleted`를 보낸다.
2. [TurnController](../Assets/Scripts/Turn/TurnController.cs)가 결과를 `CurrentYutResult`에 저장하고 소환·이동 버튼을 표시한다.
3. 플레이어가 버튼을 누르는 순간 해당 결과에 사용할 행동이 확정된다. 이동 중에는 버튼 패널을 유지하고 소환 버튼을 어둡게 표시한다. 소환을 선택하면 결과를 넘겨 소환을 요청한다. 이동을 선택하면 아군과 도착 후보를 클릭하는 입력을 받아 전달한다. 구체적인 배치와 이동 처리는 [윷 행동 명세](YutActionSpec.md)를 따른다.
4. 소환 또는 이동이 성공하면 `TurnController`가 윷 결과와 행동 선택 상태를 비운다.
5. `GameSpeedButton`은 게임 시작 시 1배로 설정하고, 클릭할 때마다 **1배 → 2배 → 4배 → 1배**로 순환한다. `Time.timeScale`에 배속을 적용하며 버튼의 숫자도 현재 배속으로 갱신한다. 선택한 배속은 턴·웨이브가 바뀌어도 유지하고, 컴포넌트가 비활성화되거나 씬에서 제거되면 1배로 복원한다.

### 턴·웨이브 연결 골격

- `TurnController`가 현재 턴 번호를 보관한다. `currentTurnNumber`는 0부터 시작한다. 한 턴에 한 웨이브이므로 해당 번호를 `WaveManager.StartWave`에 전달한다. 별도의 웨이브 번호 증가는 두지 않는다.
- `StartTurn → BeginPreparation`, 전투 시작 버튼의 `StartBattle → WaveManager.StartWave → Wave.StartWave` 호출 경로를 연결했다.
- `Wave.Completed → WaveManager.WaveCompleted → TurnController.EndBattle`로 웨이브 완료를 전달한다. 하트가 남은 중간 웨이브는 `EndTurn → StartTurn → BeginPreparation`으로 바로 이어지고, 마지막 웨이브는 `BattleWon`을 보낸다.
- 예정된 적의 소환이 끝나고 남은 적이 없으면 웨이브 완료 알림이 자동으로 발생한다. 턴 번호 증가는 `EndTurn`에 구현했다. 준비 단계의 나머지 상태·입력 제한은 후속 구현 범위다.
- 웨이브 관련 데이터 구조와 호출 관계는 [클래스별 책임과 현재 연결](WaveSpec.md#클래스별-책임과-현재-연결), 실제 연결 상태는 [씬 구성과 구현 상태](WaveSpec.md#씬-구성과-구현-상태), 미구현 항목은 [미정 및 후속 범위](WaveSpec.md#미정-및-후속-범위)에 기록한다.

## 후속 범위

- 턴 시작 시 준비 단계로 진입하고, 윷 행동 완료 후에도 준비 단계를 계속할 수 있게 한다. 별도의 전투 시작 버튼으로 준비 단계를 마치고 이번 웨이브 실행을 요청한다.
- [웨이브의 완료 알림](WaveSpec.md#완료-알림)과 위 다음 준비 단계 전환을 기준으로 준비 단계의 나머지 상태·입력 제한을 연결한다.
- 재화 잔액과 실제 던지기 비용 차감은 후속 구현이다. 백도 결과를 폐기할 때 환급 처리를 호출하지 않는다.

## 검증 상태

2026년 11월 17일 Unity Play Mode에서 빈 전장의 백도 결과 표시와 재던지기, 도 결과와 소환·이동 버튼 표시, 도 아군 소환 후 던지기 버튼 복원, 개 결과에서 이동 선택 시 소환 버튼 어두워짐, 1번 칸 아군 선택과 3번 칸 이동 후 던지기 버튼 복원을 확인했다. 검증 후 편집 모드로 돌아왔다.

프로젝트 스크립트의 C# 컴파일과 [ThrowYut 씬](../Assets/Scenes/ThrowYut.unity)의 Cell ID 29개를 확인했다. Unity Play Mode에서 걸 결과로 `Cell 01`에 아군을 소환하고, 다음 윷 결과로 `Cell 05`에 도착 후보를 표시한 뒤 클릭해 이동하는 흐름을 확인했다.

Next Wave 버튼 추가 후 C# 빌드는 경고 0개·오류 0개로 통과했다. Unity Play Mode에서 적 10마리 전원 처치 → 승리 패널과 버튼 표시 → 버튼 클릭 → 패널 닫힘과 HUD Wave 1에서 Wave 2로 변경, 처치 수 0 초기화, 아군·하트 유지까지 확인했다. 당시 첫 웨이브만 등록되어 두 번째 준비 단계에 `0 / 0`이 표시되는 것을 확인했다. 이후 기존 [Wave2 데이터](../Assets/Wave2.asset)를 씬의 `WaveManager.waves[1]`에 연결했다. 두 번째 웨이브는 데이터의 각 적 종류 3마리씩, 총 6마리를 사용한다. 이 추가 연결은 데이터와 씬 참조를 확인했으며 실제 두 번째 전투 실행은 아직 재검증하지 않았다.
