# 천명전 다음 전투 보상 배율 — 작업39

준비 중 천명전1개를 소비해 바로 다음 전투의 처치·기본 완료 보상을2배로 예약한다. 같은 준비의 추가 사용은 무소비이며 남은 보유를 유지한다. 전투 중 사용은 차단한다. 일반/빠른 처치2→4·일반 웨이브 완료60→120·보스 처치100→200이다. 누수가 있어도 생존 완료하면120을 지급한다.10웨이브에서도 사용할 수 있으며 보스200 지급 뒤 승리하고 일반 완료 보상을 추가하지 않는다.

예약은 유효 전투가 시작될 때 활성 전투 효과로 전환한다. 잘못된 전투 시작은 예약을 복원한다. 완료 보상 정산이 끝난 뒤 다음 준비 전에 해제하고,승리/패배에서도 해제한다. 다음 전투에는 남지 않는다. 천운부의 던지기 할인은 보상 기준액을 바꾸지 않는다. 새 씬은 예약/활성false다.

기존 StageItemUseController의 소비/잠금 경로와 일반재화 실제 지급/HUD·처치 팝업 경로를 사용한다. 배율은 TurnController에서 하나의 값으로 제공하며 지급 직전에만 적용한다. 기본 데이터2/2/100/60과 던지기 비용은 유지한다. 새 판/재도전40과 결과/정산 UI41~46은 후속이다.

## 실행 흐름

1. [HeavenlyMandateEffect](../Assets/Scripts/Turn/HeavenlyMandateEffect.cs)는 사용 실행기에 등록한다. TryApply는 HasPending을 켜고 기존 사용 거래가 보유1개를 소비한다. 예약/활성 중에는 CanApply가 거짓이어서 중복 보유가 있어도 소비하지 않는다. 구매만으로 효과를 적용하지 않는다.
2. [TurnController.StartBattle](../Assets/Scripts/Turn/TurnController.cs)는 기존 입력 검사를 통과하면 스폰 전 BeginBattle로 HasPending→IsActive를 전환한다. 유효한 전투를 시작하지 못하면 CancelBattleStart가 예약을 복원한다. BattleRewardMultiplier는 활성 전투에서만2이며 평소에는1이다.
3. [EnemyKillRewards.OnKill](../Assets/Scripts/UI/EnemyKillRewards.cs)은 기본2/2/100에 현재 배율을 곱해 실제 지급하고, 기존 HUD와 팝업은 실제 지급액4/4/200을 사용한다. 보스 처치 이벤트는 기존 WaveManager 순서대로 지급이 끝난 뒤 승리를 전달한다.
4. EndBattle은 일반 완료 기본60에 배율을 곱해120을 지급한다. 지급 콜백까지 배율을 유지하고 다음 준비/완료 관찰자 호출 전에 FinishBattle로 해제한다. endingBattle 중 StartBattle도 차단해 완료 콜백이 동기적으로 다음 전투를 재시작하지 못하게 한다. 승리/패배는 결과 이벤트 전에 해제한다.
5. InventoryUI는 기존 도깨비 윷 대기와 천명전 대기를 함께 두 줄로 표시한다. [HeavenlyMandateBuilder](../Assets/Editor/HeavenlyMandateBuilder.cs)가 실제 씬의 효과/사용 실행기/Turn 참조를 연결하고 저장 후 재로드 검사한다. 싱글톤·별도 지갑·중복 보상 데이터는 추가하지 않는다.

정산 UI43·결과/재도전40~46 전체 완료로 확대하지 않는다. 보상 배율은 일반재화 지급액에만 적용하며 아이템 보상·특별재화·던지기 비용에는 적용하지 않는다.
