# 도깨비 윷 다음 던지기 효과 — 작업38

준비 사용 시1개를 소비하고 다음 유효 던지기1회에 대기 효과를 예약한다. 이미 확정된 결과는 바꾸지 않는다. 대기 중 중복 사용은 무소비이며 던지지 않고 전투를 해도 다음 준비까지 유지한다. 실패한 던지기(재화/상태/윷 준비 불충족)는 대기를 소비하지 않는다. 새 씬에서는 초기화한다.

정확한28개 동일 확률 구간으로 빽도1/28·도3/28·개6/28·걸4/28·윷7/28·모7/28을 추첨한다. 윷/모 각25%이며 나머지50%는 기본 비율대로 배분한다. 표식 윷을 매번4개 중 균등 선택하고, 추첨 결과와 일치하는 실제 면 조합을 선택해 원래 연출을 재생한다. 마지막 면·결과 이미지·완료 이벤트는 일치해야 한다. 효과 없는 던지기는 기존 독립50% 면 판정을 유지한다.

정상 결제와4개 윷 준비 검증 뒤 대기 효과를1회 확정한다. 천운부 비용16/기본20은 기존 현재 비용을 사용한다. 인벤토리 하단에 다음 던지기 대기 상태를 표시한다. 천명전39는 후속이다.

## 실행 흐름

1. [DokkaebiYutEffect.TryApply](../Assets/Scripts/Turn/DokkaebiYutEffect.cs)는 기존 StageItemUseController의 사용 잠금 안에서 HasPending을 확정한다. 보유1개 소비 알림은 대기 확정 뒤 나간다. HasPending이면 CanApply가 거짓이므로 추가 보유 fixture가 있어도 소비하지 않는다. 현재 윷 결과·재화·구매 이력을 수정하지 않는다.
2. [YutThrowController.Throw](../Assets/Scripts/Yut/YutThrowController.cs)는 기존 단계/미사용 결과/4개 윷 준비 검사를 거쳐 IsThrowing을 잠그고 현재 비용을 결제한다. 성공한 경우에만 효과의 TryConsumeForThrow로28구간 결과를1회 추첨하고 대기를 해제한다. 유효 던지기 시작이 소비 시점이며 연출 종료 때 추가 결제하지 않는다.
3. 매번 무작위 표식 윷을 먼저 정하고 CreateFaceMask가16개 면 조합 중 추첨 결과와 일치하는 조합을 모아1개를 선택한다. [YutStick.Throw(face,marked)](../Assets/Scripts/Yut/YutStick.cs)는 지정된 최종 면으로 기존 현재면→최종면/표식 애니메이션을 재생한다. 기본 Throw(bool)는 기존50% 면 추첨을 수행한 뒤 같은 연출 경로에 위임한다.
4. 완료 판정은 실제4개 면을 다시 집계한다. 기존 LastResult·결과 이미지·ThrowCompleted 경로로 전달하므로 표시만 바꾸지 않는다. 다음 던지기는 HasPending=false라 기본 독립 면 추첨으로 복귀한다. 빽도의 기존 행동 불가 자동 소비도 유지한다.
5. InventoryUI는 보유에서 아이템이 사라진 뒤에도 하단에 ‘도깨비 윷: 다음 던지기 대기 중’을 표시한다. 실제 던지기 뒤에는 표시가 해제된다. [DokkaebiYutBuilder](../Assets/Editor/DokkaebiYutBuilder.cs)가 효과/실행기/던지기/상태 표시를 씬에 연결하고 저장 후 재로드 검사한다.
