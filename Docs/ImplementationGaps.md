# 기획서 대비 구현 미충족 누적 목록

> 2026-11-18 후속 구현: 상단 특별재화 HUD, 시작0 잔액, 특별소환창 열기·닫기와 준비/전투 차단을 연결했다. 작업08에서 일반 유닛 완주 지급을 연결하고 SpecialCurrency를StageCurrency.SpecialBalance의 HUD 호환 계층으로 통합했다. [특별소환 UI 명세](SpecialSummonUISpec.md)가 최신 연결 범위다. 최초 정적 점검의 “창·잔액 자체가 없다”는 설명은 후속 구현으로 대체한다. 아이템 지급·30 차감·특별소환 인구 검사·추첨·백호 생성은 남아 있어 GAP-004~006은 완결 처리하지 않는다.

- 기준: [Google Docs 탭 4](https://docs.google.com/document/d/1hI6NtOWNZ2KTU-vgrUT0q4KMR9PjlM2E5JoXmvvcwuU/edit?tab=t.blkk5zag95yu), 개발 전달본 v1.3 (2026-11-17).
- 점검일: 2026-11-18. 점검 완료 범위: 01~23장 및 26~27장. 24·25장은 아직 개별 점검하지 않았다. 22·23·26·27장은 각 요청에서 링크에 다시 접속해 최신 탭 4 본문을 내보내 확인했다. 21장이 참조하는 29장 확정안도 해당 UI 범위에서 함께 확인했다.
- 최초 누적 점검은 로컬 작업본의 미커밋 변경을 포함한 코드·씬·프리팹 정적 대조이며 Play Mode/빌드를 실행하지 않았다. 이후 구현의 실행 검증은 아래 ‘구현 진행 기록’에 작업별로 구분한다.
- 중복 요구사항은 기존 ID에 장과 세부 조건을 추가한다. 누적 식별 항목은37개이며 GAP-017/016/022/019/024/014/015/001/033 완료 후 현재 미해결은28개다(기능·규칙 대조28개, 개발 문서 보완0개). ID는 재사용하거나 당겨 바꾸지 않는다. 개별 수정 작업 수나 완료율을 뜻하지 않는다.
- 최초 점검은 기능 구현을 포함하지 않았다. 2026-11-18 사용자 지시에 따라 아래 작업 순서로 구현·검증을 진행하며, 한 작업씩 완료 후 보고한다. 작업17~20의 기존 대조 전용 조건과 선택 보완 분리는 유지한다.
- 사용자 확정(2026-11-18): 실제 일반 소환 위치는 Cell 01이 맞다. 현재 DeploymentCellId = 1을 소환 위치 결함으로 보거나 Cell 00으로 변경할 대상으로 삼지 않는다. 코드의 StartCellId = 0이라는 명칭과 소환 칸을 구분해 문서화한다. 특별유닛도 같은 시작 칸에 생성한다는 기획 조건에 따라 특별소환 연결 위치 역시 Cell 01로 대응한다.
- 사용자 정정(2026-11-18): 16장 말미의 '딱 하나 구미호의 심장 또는 영혼의 결정' 및 이어지는 효과·개발자 선택 문구는 고려하지 않는다. 단일 아이템 축소 해석을 철회하고 본문의 고정 5종 진열·6종 아이템 표·사용 규칙으로 재점검한다. GAP-021과 천운부 할인·천명전 배율을 복원한다. 구미호의 01장 제외와 16장 포함은 문서 불일치로 구분하고 특정 5종을 새로 확정하지 않는다. GAP-013 제외는 유지한다.
- 10장에는 피해·공격 판정의 개발 완료 전달과 추가 설계 질문·신규 구현 요청 중단이 명시되어 있다. 이번 사용자의 10장 점검 요청에 따라 차이만 기록하며, 이 기록을 변경 승인이나 신규 구현 지시로 간주하지 않는다. 미확정 판정·속도 수치를 새로 정하지 않는다.

## 한 번에 완료·검증할 작업 순서

- 아래 작업01~45는 한 가지 결과물을 구현하거나 대조하고, 바로 완료 여부를 확인할 수 있도록 나눈 권장 작업 단위다. 작업46은 마지막 통합 점검이다. 소요시간이나 한 번의 응답 안에서 무조건 끝남을 보장하는 추정치는 아니다.
- 각 행의 '범위'와 '완료 기준'까지 한 작업으로 묶는다. 선행 작업이 끝나면 순서대로 진행하며, 기반 코드만 만들고 화면/동작 연결을 무기한 남기는 방식으로 완료 처리하지 않는다. 기존 GAP ID는 요구사항 식별자로 유지하고 작업 번호와 구분한다.
- GAP-004(백호/특별소환), GAP-007(상점/아이템), GAP-020(정보 내용/연출), GAP-037(결과 내용/연출) 등은 여러 작업으로 분할했다. 퇴장과 도착UI, 도깨비 윷 사용과 확률처럼 함께 검증할 기능은 한 작업으로 묶었다.
- GAP-008의 기존 입력 차단은 작업02에서 완료하고, 이후 새로 추가하는 특별소환/상점/아이템 입력 차단은 해당 작업의 완료 조건에 포함한다. 백호가 필요한 인구·퇴장·미리보기는 작업25에서 실제 백호 분기까지 연결한다.
- 작업17~20은 10장의 개발 완료 전달과 변경 지시 중단 조건을 유지하는 대조 작업이다. 기존 완료 근거와 실제 동작을 확인해 판정하며, 이 정렬을 재구현 지시로 해석하지 않는다. 확정되지 않은 수치는 새로 정하지 않는다.

### GAP-028 — 전투마다 첫 공격 준비 상태 초기화 보장

### GAP-029 — 도사·궁수 투사체의 동일한 일정 속도 이동

- 요구: 마법탄·화살은 같은 일정 속도로 현재 표적을 추적하며, 거리와 표적 이동에 따라 비행 시간이 달라진다. 도착 시각에 맞추는 가감속은 없다. 구체적인 속도는 기존 구현 설정을 참조한다.
- 현재: ProjectileAttack은 flightDuration을 넘기고 HomingProjectile은 발사 위치와 매 프레임 표적 위치 사이를 elapsed/flightDuration 비율로 Lerp한다. 현재 도사·궁수의 1·2성은 flightDuration=0.3으로, 거리가 달라도 정해진 시간에 도착하는 방식이다.
- 차이: 동일 비행 시간은 동일 속도가 아니며 움직이는 표적의 위치 변화에 따라 프레임 이동량도 달라진다. 현재 코드에는 문서가 참조하는 명시적인 이동 속도 값이 확인되지 않는다. 새로운 속도 숫자를 임의로 정하지 않는다.

### GAP-030 — 발사 후 공격자 기준 사거리 이탈 시 투사체 소멸

- 차이: 발사 후 원래 공격자의 사거리 밖으로 나간 표적도 살아 있고 같은 활성 버전이면 계속 추적해 피해를 줄 수 있다. 사망·탈출·재사용 시 소멸, 다른 적으로 재표적하지 않음, 피해 한 번 적용은 이미 구현되어 있다.

### GAP-031 — 전사·창병의 공격 시작 표적 유지와 근접 타격 판정

- 요구: 전사·창병은 공격 시작 때 사거리 안에 있던 표적을 타격까지 유지한다. 이후 거리 이탈만으로 취소하지 않는다. 사망·탈출이면 피해 없이 동작을 마치고 다른 적에게 진행 중 공격의 피해를 옮기지 않는다. 기존 대기시간은 유지한다.

- 후보/성공 처리: 현재 등록 후보 백호1종, 향후 후보 추가 가능한 무작위 선정, 공통 시작 칸 생성, 성공 후 창 자동 닫기를 기존 GAP-004에 포함한다. 특정 백호 고정 초상이나 오른쪽 윷 패널의 새 특별소환 버튼을 별도 구현 요구로 추가하지 않는다.
- 신규 ID 없이 필수37개(기능·규칙36개, 개발 문서1개), 선택3개 유지. 24·25장은 아직 개별 점검하지 않았다. 정적 점검이며 실제 화면의 너비·색상·마우스 강조 및 성공/실패 흐름은 Play Mode로 검증하지 않았다. 이번 수정은 누적 문서에 한정한다.

## 선택 보완 항목 — 필수 미충족 개수에서 제외

### OPT-001 — 전체·배경음악·효과음 설정 창

- 근거: 17장은 설정 창에 '시간 없으면 skip'이라고 명시한다. 생략하기로 확정된 것은 아니지만 생략 가능한 범위이므로 필수 GAP 개수와 분리한다.
- 현재: 설정 버튼 모양은 있으나 화면 열기·세 음량 조절·실제 오디오 반영이 없다.
- 보완 범위: 설정 버튼에서 전체/BGM/SFX 조절 창을 열고 실제 음량에 연결. 해상도·전체화면·그래픽 품질·설정 영구 저장 등 17장에 없는 기능은 요구로 추가하지 않는다.
- 상태: 미구현인 선택 보완 항목. 현재 전체 개수는 문서 상단과 OPT-002 끝에 따른다.

### OPT-002 — 일시정지 메뉴와 ESC·계속하기·나가기 확인 연결

- 근거: 21장에는 ESC 일시정지 기본안과 시간 부족 시 생략 가능이라는 문구가 있다. 실제 생략 확정은 아니지만 필수 GAP 개수와 분리한다.
- 현재: 일시정지 UI·ESC 입력·시간 정지/복원·계속하기·메인/종료 메뉴와 확인창이 없다.
- 채택 시 조건: 전투 시간을 멈추고 배속 상태와 정합화한다. 메인/종료는 진행 소멸 확인을 띄우고 확인 전 초기화하지 않는다. 취소하면 기존 일시정지를 유지하며 확인 시 초기화/이동·종료한다. 일시정지 중 준비 조작은 차단한다.
- 분리: 전투 중 편성 조작 차단은 GAP-008, 결과창 메인 이동·재도전은 GAP-009/011/037로 유지한다.
- 21장까지 선택 보완 2개(OPT-001 음량 설정, OPT-002 일시정지). 현재 전체는 OPT-003 끝의 개수로 갱신한다.

### OPT-003 — 한 장짜리 게임 방법 안내와 물음표 진입 버튼

- 근거: 23장은 준비 화면의 한 장 안내를 완료 기준으로 쓰지만, 같은 문서 후속 정리에는 게임 방법 안내를 '시간 남으면 하기'로 둔다. 준비 화면 안내와 메인 물음표 언급이 함께 있어 위치를 임의로 하나로 확정하지 않는다. 실제 규칙의 확정 여부를 다시 질문할 항목이 아니라 문서 표현과 연결 상태를 구분해 기록한다.
- 현재: Assets/Scripts와 Title/ThrowYut 씬에서 게임 방법 안내 제어·진입 버튼 연결을 확인하지 못했다.
- 상태: 미구현인 선택 보완. 안내 내용·상세 레이아웃을 임의로 새로 설계하지 않는다. 23장 기본안은 한 장 UI이며 챕터별 튜토리얼·강제 플레이 교육을 요구하지 않는다.
- 현재 선택 보완 총3개. 누적37개 중 GAP-017/016/022/019 완료로 현재 필수 미해결은33개다. 과거 작업 기록의36개·35개·34개는 해당 작업 시점의 수치다.
