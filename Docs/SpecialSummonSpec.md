- 후보 배열이 비었거나 null/인구3이 아닌 후보가 있거나,필수 참조가 유효하지 않으면 실행하지 않는다. 임의의 다른 일반 유닛으로 대체하지 않는다.

## 코드 흐름

1. [SpecialSummonController](../Assets/Scripts/Turn/SpecialSummonController.cs)의 `CanSummon`은 준비 상태·후보·잔액·배치 조건을 확인한다. `TrySummon`도 이를 새로 확인한 뒤 후보를 뽑아 공통 배치 경로에 전달한다.
2. [YutActionController.TryDeployPaidAlly](../Assets/Scripts/Yut/YutActionController.cs)는 배치 조건을 검사하고 IsResolvingSummon을 잠근다. [TurnController](../Assets/Scripts/Turn/TurnController.cs)의 준비 입력과 StartBattle은 이 잠금 중 재입력을 거부한다.
3. [StageCurrency.TrySpendSpecial](../Assets/Scripts/Turn/StageCurrency.cs)의 내부 트랜잭션 경로는 차감하되 알림을 보류하고 배치를 확정한다. 배치 실패 시 조용히 잔액을 복원한다. 성공하면 이미 배치된 유닛과 최종 잔액을 관찰할 수 있는 상태에서 SpecialChanged를 보낸다. 기존 SpecialCurrency 호환 계층과 HUD/열린 창의 숫자가 같은 알림으로 갱신된다.
4. 공통 `DeployAtStart`는 풀·시작 칸·인구를 재검사하고 풀 요청/점유 등록/전투 연결/자리 배치를 수행한다. 등록 실패는 풀에 반환한다. 이후 `Summoned(Ally)`를1회 보내고 finally에서 잠금을 해제한다. 알림 중 실행/윷/일반 배치/이동/진화/전투 재입력은 차단한다.

씬의 TurnController 오브젝트에 실행기를 추가해 TurnController/YutActionController/StageCurrency 및 WhiteTiger 후보를 직렬화 참조한다. 싱글톤·정적 잔액은 사용하지 않는다. 이번 단계에서는 `SpecialSummonController.TrySummon()`으로 실행하며 기존 랜덤 소환 버튼은28에서 연결한다.

## 검증 범위

실제 ThrowYut 씬의 복사본 Play Mode에서 잔액/인구 경계·실행 직전 조건 변화·후보/참조 오류·배치 실패 복구·재입력·입력 상태·윷 결과 유지·HUD 잔액 동기화·이월/새 판 초기화를 검증한다. 테스트 재화/후보/배치는 메모리 fixture이며 씬에 저장하지 않는다. 전체 빌드·수동 완주는 이번 범위가 아니다.

Unity6000.3.28f1에서474개 검사 통과·검사 구간 런타임 오류0. [검증 코드](../Assets/Editor/SpecialSummonExecutionVerification.cs)·[결과](Verification/SpecialSummonExecutionVerification.json).

- 실제 잔액0/29/30/45/60 × 시작 인구0~6의35조합. 성공 시 정확히30/백호1기/인구3 증가·알림1회,실패 시 무차감/무생성/무알림을 확인했다.
- 잔액45→29/시작 인구0→4의 조건 변경 뒤 실행 거부,빈/누락/인구1 후보,시작 칸/풀 누락,비활성·일시정지·던지기·승패·하트0·준비 밖·실제 전투 상태 차단을 확인했다. 일부 상태는 실행 중 속성 변경 fixture이며 UI 클릭 검증이 아니다.
- 잔액/성공 콜백에서 특별·일반 소환/윷/전투를 재입력해도 중복 처리하지 않는다. 콜백 안에서 이미 백호 점유와 차감 후 잔액이 함께 보인다. 배치 commit이 실패하거나 예외를 던지는 fixture는 잔액 복원/무알림을 확인했다.
