# 최종 승리·패배 깃발

## 표시 조건과 실제 값

- `TurnController`의 기존 `BattleWon` / `BattleLost` 이벤트를 사용한다. 승패 판정, 마지막 웨이브 판정, 완료 보상 계산은 바꾸지 않는다.
- 중간 웨이브는 기존 두루마리와 다음 준비 단계로 진행한다. 마지막 등록 웨이브 방어 성공 또는 하트 0일 때만 결과 깃발을 표시한다.
- `도달한 웨이브`는 `CurrentTurnNumber + 1 / WaveManager.WaveCount`이다. 현재 2개에서 10개 이상으로 웨이브 데이터가 늘어나도 UI 수정이 필요 없다.
- 숫자·문구는 확정한 Typography PNG를 사용한다. 0~10은 제공 이미지, 11 이상은 0~9 이미지를 조합한다.
- 승리 화면에 보스 처치 보상이나 추가 재화 행을 넣지 않는다.

## 화면과 연출

- 1920×1080 기준 화면 중앙, 깃발의 보이는 크기는 720×850이다. 상단 봉, 제목, 웨이브, 버튼은 하나의 부모 아래에서 함께 움직인다.
- 승리: 붉은 테두리의 밝은 천, 붉은 제목. 패배: 회색 천과 먹색 제목. 확정한 원본 PNG를 사용한다.
- 0.00~0.20초: 배경을 64% 어둡게 한다.
- 0.12~0.68초: 위쪽 1,130px에서 감속하며 내려온다.
- 0.68~0.94초: 최대 8px / 0.35도 범위의 작은 흔들림이 감쇠한다.
- 0.76~0.96초: 버튼이 나타나며, 0.98초부터 입력할 수 있다.
- 결과가 뜨면 전투 시간을 멈춘다. 등장 연출과 버튼은 실제 시간으로 작동하며 배속의 영향을 받지 않는다. 중복 결과 알림으로 연출을 다시 시작하지 않는다.
- 결과 화면은 뒤쪽 조작을 가린다. 중간 웨이브 완료 두루마리의 준비 단계 조작 허용 규칙과는 별개다.

## 버튼

- 왼쪽 `메인화면으로`: `Title` 씬으로 이동한다. 기존 타이틀의 게임 시작 버튼은 `ThrowYut`으로 돌아온다.
- 오른쪽 `다시 도전`: 현재 게임 씬을 다시 로드한다. 웨이브·아군·하트·재화 등 씬의 진행을 초기 상태로 되돌린다.
- 각각 Normal / Pressed PNG를 교체한다. 버튼 RectTransform은 298×104로 유지하며 축소나 이동으로 눌림을 만들지 않는다.
- 승리·패배에 맞는 서로 다른 버튼 색상을 사용한다. 마우스를 떼면 기본 이미지로 돌아온다.
- 클릭 이후 중복 입력을 막고 짧은 눌림 표시 후 이동한다. 새 화면은 1배속으로 시작한다.

## Unity 연결

- `Canvas`의 `BattleStateHUD`: `TurnController`, `WaveManager`, `ResultFlag` 프리팹을 명시적으로 참조한다.
- `Assets/Prefabs/ResultFlag.prefab`: 이미지·레이아웃·테마 참조.
- `Assets/Scripts/UI/ResultFlagView.cs`: 표시, 실제 숫자 조립, 등장 연출, 버튼과 씬 이동.
- `Assets/Art/ResultFlags`: 제공한 깃발·제목·Typography·버튼 이미지와 원본 GUID.
- 이전 정적 `Victory Panel` / `Defeat Panel`은 씬에서 교체했다. 원본 HUD 이미지는 삭제하지 않는다.
- 빌드 씬 목록에 기존 `ThrowYut`과 `Title`을 함께 등록한다. 첫 실행 씬 순서는 유지한다.
- 프리팹 재생성: `Tools > Yut UI > Rebuild Result Flag Prefab`. 게임 데이터는 변경하지 않는다.

## 검증 방법

별도 Unity 프로젝트 복사본에서 `ResultFlagVerification.Run`을 실행한다. 이 검증은 테스트용 웨이브 배열을 실행 중에만 바꾸고 씬에 저장하지 않는다. 배치 검증 완료 후 해당 Unity 프로세스를 종료하므로, 작업 중인 편집기에서 직접 실행하지 않는다.

실제 전투 이벤트의 2/2 승리, 10/10 승리, 7/12 패배, 중간 웨이브 보상 73, 4개 버튼 눌림 이미지, 입력 차단, 재도전 초기화, 메인 이동과 타이틀 게임 시작을 확인한다.

## 작업41 나가기 정책 구분 (2026-11-19)

결과창의 메인/재도전은 기존 확정 버튼 입력과 짧은 눌림 후 이동을 유지한다. 진행 중 나가기는 별도 메인/종료 확인창에서 취소 보존/확인 이동을 제공한다. 결과창에 종료 버튼을 추가하지 않는다. [실행 검증과 범위](StageExitSpec.md).

## 작업42 빌드 진입 순서 (2026-11-19)

기본 빌드 시작 순서는Title→ThrowYut으로 확정/검증했다. 기존 메인·재도전은 이름으로 씬을 로드하므로 경로를 유지한다. [실제Windows 빌드 검증](BuildMainEntrySpec.md).
