# 상점 구매·보유·품절 — 작업33

2026-11-19. [고정5종 카탈로그](ShopCatalogSpec.md)의 상품을 준비 단계에서 일반재화로 각1회 구매한다. 클릭 순간 가격/잔액/준비 상태/구매 이력을 재검사한다. 성공은 정확한 가격 차감·보유1개·구매 완료를 함께 확정하고,실패/중복은 차감·지급·성공 알림이 없다.

- 구매 가능/재화 부족/구매 완료를 선택 상품과 목록에서 구분한다. 구매 완료 상품도 설명 열람은 가능하다.
- 구매 이력과 현재 보유 목록을 분리한다. 창 닫기/재열기/다음 웨이브/아이템 소비 뒤에도 구매 완료는 유지한다. 새 씬/새 판에서는 초기화한다.
- 구매 중 잔액/보유/성공 알림에서 구매·윷·소환·이동·진화·전투를 재입력해도 중복 처리하지 않는다.
- 인벤토리9칸/사용 화면은34,각 아이템의 실제 효과는35~39에 남긴다. 천운부의 구매 즉시 실제 할인도36 범위이며 이번33은 결제·보유·품절만 연결한다.

## 실행 흐름

1. [ShopCatalogUI](../Assets/Scripts/UI/ShopCatalogUI.cs)의 BuySelected가 열린 준비 상점의 선택 상품을 [ShopPurchaseController](../Assets/Scripts/Turn/ShopPurchaseController.cs)에 전달한다. 실행기는 실제 등록된 상품 에셋인지,구매 이력/보유 중복이 없는지,잔액과 준비 상태가 유효한지 다시 검사한다. 복제/미등록 에셋의 임의 가격은 받지 않는다.
2. IsPurchasing으로 재입력을 잠근 뒤 [StageCurrency](../Assets/Scripts/Turn/StageCurrency.cs)의 내부 TrySpend(amount,commit) 경로에서 일반재화를 차감하고 알림을 보류한다. [StageInventory](../Assets/Scripts/Turn/StageInventory.cs)에1개를 추가하고 구매 이력을 기록한 후에만 일반재화 변경→보유 변경→구매 성공 알림을 보낸다. 배치가 아닌 보유 확정 실패도 잔액을 조용히 복원하는 같은 거래 구조다.
3. 모든 알림 동안 TurnController의 준비 입력과 StartBattle도 구매 잠금을 검사한다. finally에서 잠금을 해제한다. UI는 구매 완료 상품의 아이콘/가격을 어둡게 하고 목록 배지·선택 상태를 ‘구매 완료’로 표시한다. 재화 부족과 구매 가능도 즉시 갱신하며 버튼의 위치/크기는 바꾸지 않는다. 구매 성공 후 상점은 열린 상태를 유지한다.
4. 구매 이력은 ShopPurchaseController,현재 보유는 StageInventory의 별도 HashSet이다. 내장 TryRemove는 후속 아이템 효과 처리용 내부 API이며 소비 후에도 구매 이력은 지우지 않는다. 두 컴포넌트 모두 씬 수명이고 싱글톤·정적 보유·웨이브별 초기화를 사용하지 않는다.

[ShopPurchaseBuilder](../Assets/Editor/ShopPurchaseBuilder.cs)가 실제 씬의 실행기/보유 저장소와5개 상품,목록/선택 상태 Text를 연결한다. 상점 생성기는 에셋 저장 뒤 선택 테두리를 다시 연결하고,구매 생성기는 씬을 저장한 뒤 다시 열어5개 참조가 남는지 검사한다.

## 검증

[ShopPurchaseVerification](../Assets/Editor/ShopPurchaseVerification.cs)에서 실제 씬 Play Mode117개 검사 통과·검사 구간 런타임 오류0. [결과](Verification/ShopPurchaseVerification.json).

- 5종 각각 가격-1 거부/정확한 가격에서 실제 구매 버튼 클릭·한 번 차감·보유1개·품절1회,일반재화 HUD 반영을 확인했다.
- 잔액/보유/성공 알림 안에서 이미 최종 차감·보유·품절이 함께 보이고,동일/다른 상품 재구매와 일반/특별 소환·윷·전투 재입력은 거부한다. 충분한 재화를 다시 지급해도 구매 완료 상품은 재구매할 수 없다.
- 창 닫기/재열기,실제 다음 웨이브 준비에도 품절/보유를 유지했다. 영혼의 결정의 보유를 내부 소비 fixture로 제거해도 재입고되지 않는다. 실제 사용 효과/인벤토리 버튼 검증으로 확대하지 않는다.
- 일반재화1000 fixture에서5종 합계600을 차감해400/보유5개/전부 품절을 확인했다. 특별재화45는 유지했다. 새 씬은120/보유0/전부 미구매로 돌아온다.
- 닫힌 창의 늦은 클릭,미등록 복제 상품/null,전투/일시정지/던지기/승패/비활성 보유 저장소·재화·실행기의 거부를 확인했다. 일부 상태는 메모리 속성 fixture다.

첫 실행에서 이전 상점 씬의 첫 선택 테두리가 저장 파일에 빠져 있음을 확인했다. 저장 후 재로드 검사를 추가하고 참조를 복원한 뒤 전체 구매 검사와 씬 재시작을 통과했다. 초기 에디터 검색 인덱스 예외는 게임 검사 구간 앞이며 오류0은 게임 검사 구간을 뜻한다.
