## 확정 범위

ImplementationGaps 작업34와 원문20장 기준. 기존 오른쪽 인벤토리의 위치·등장 연출·9칸 배치를 유지하고, 고정5종 구매 보유 데이터를 연결한다. 상품 순서로 보유 품목만 앞에서 채우며 나머지 슬롯은 빈칸으로 둔다. 빈칸은 선택되지 않는다.

보유 품목을 선택하면 같은 상품 데이터의 아이콘·이름·배경·최신 효과를 표시한다. 사용형4종은 사용하기 버튼을 제공한다. 천운부는 보유형으로 사용 버튼을 숨기고 적용 상태 표시 경로를 제공한다. 실제 효과가 연결되기 전에는 보유 중으로 표시한다.

준비 단계에서만 열기·선택·사용을 허용하고 던지기·전투·일시정지·승패에서는 차단한다. 닫힌 창의 늦은 사용 콜백도 무시한다. 상점/개별 정보창과 동시에 열리지 않게 하고, 전투 진입 시 닫는다.

사용 실행기는 효과 처리기를 명시적으로 등록받는다. 연결된 효과가 없거나 실패하면 무소비다. 성공한 사용형만1개 소모하며 처리 중 재입력을 막는다. 실제 효과 구현과 소비 검증은35~39이며,34에서는 테스트 전용 효과로 호출 경로·성공/실패·상태 차단을 검증한다. 플레이용 효과/보상·할인·확률은 추가하지 않는다. 천운부 적용중 표시도 실제 할인 효과36의 상태에 연결할 수 있게 한다.

## 구현 흐름

1. [InventoryUI](../Assets/Scripts/UI/InventoryUI.cs)는 활성화 때 StageInventory.Changed를 구독하고 고정5종 순서로 실제 보유만9칸에 배치한다. 빈칸 강제 콜백도 거부하며 선택 시 동일 ShopItemDefinition의 아이콘·이름·배경·효과를 설명창에 표시한다. 선택 품목이 소모되면 선택을 지우고 남은 보유를 앞에서 다시 채운다. 뒤로는 설명창만 닫고, 인벤토리 닫기/재열기는 선택을 초기화한다.
2. UseSelected→[StageItemUseController.TryUse](../Assets/Scripts/Turn/StageItemUseController.cs)는 보유/준비/일시정지/던지기/실행기 활성 상태와 효과의 CanApply를 재검사한다. IsUsing 잠금 아래에서 효과 TryApply 성공 후1개를 소모한다. 실패·미등록·천운부 직접 사용은 무소비다. 효과 처리기는 성공 여부를 반환하고 자신의 상태/지급만 담당하며 보유를 직접 수정하지 않는 계약이다. Register/Unregister로 명시적으로 연결하고 싱글톤을 사용하지 않는다.
3. [TurnController](../Assets/Scripts/Turn/TurnController.cs)의 준비 입력과 StartBattle은 사용 잠금을 검사한다. 인벤토리 열기 때 상점/개별 정보/사거리를 닫고 기존 전투 진입 정리·토글 동기화를 유지한다. UI는 비활성 조건을 프레임마다 검사하며 닫힌 창 콜백을 실행하지 않는다.
4. [InventoryBuilder](../Assets/Editor/InventoryBuilder.cs)가 기존 슬롯 위치/크기·드롭 연출을 유지하고 실제 버튼/아이콘/선택 표시/설명창/사용/뒤로를 연결한다. 기존 아이템 UI 아트를 재사용했다. 설명창 원본의 흰 바깥 배경은 전용 [UI 셰이더](../Assets/Scripts/UI/InventoryFrame.shader)와 머티리얼로 렌더링 때 제거한다. 원본 PNG는 수정하지 않았다. 저장 후 씬을 다시 열어9칸 참조를 검사한다.
