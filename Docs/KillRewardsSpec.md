# 적 처치 보상과 획득 표시 (2026-11-18)

작업21은 사용자 지정 Google Docs 탭4를 기준으로 진행하는 ImplementationGaps 작업표를 따른다. 작업12에서 다시 내보낸 원문14장은 일반·빠른 적을 각각2,최종 보스를100으로 정한다. 빠른 적1/보스 미지급이던 기존 코드와 씬을2/2/100으로 맞췄다. 이 문서의 이전 빠른 적1 기록은 이 기준으로 대체한다. 천명전2배는 작업39에 남고,보스 정산 뒤 즉시 승리는 [작업23](BossOutcomeSpec.md)에서 연결했다.

- 실제 체력이 0이 되어 Wave의 생존 목록에서 제거되는 순간 한 번 지급한다. 사망 연출 종료나 풀 반환에서는 추가 지급하지 않는다.
- 탈출은 처치 보상을 지급하지 않는다. 패배·승리로 끝난 뒤에는 추가 지급하지 않는다.
- StageCurrency에 바로 합산하므로 상단 잔액과 기존 비용 부족/던지기 가능 여부도 갱신된다. 웨이브 완료 보상은 별도로 유지한다.
- 표시 내용은 배경 없이 작은 코인 아이콘과 실제 지급액 `+2` 또는 `+100`이다. 처치 위치 위에서 약0.8초 동안24 UI픽셀 위로 떠오르며 후반에 투명해진다. 표시 후 적이 움직이거나 재사용되어도 따라가지 않는다. 정수 상한에서2 중1만 지급되면 `+1`을 표시한다.
- 표시 금액은 실제 지갑에 추가된 금액이다. 정수 상한에 도달해 수입이 제한될 때에도 실제 수입과 일치한다.
- 금액 표시는 클릭을 받지 않는다. 게임 일시정지 시 함께 멈추며, 최종 승리·패배 시 정리한다.
- Unity Canvas의 Enemy Kill Rewards 컴포넌트에서 일반/빠른/보스 보상과 표시 시간을 조정할 수 있다. 현재 씬 값은2/2/100이며 코인과 숫자는 기존 UI 에셋을 사용한다.

## 지급 경로와 종료 보호

`Enemy.TakeDamage→Defeated→Wave.DefeatEnemy→WaveManager.EnemyDefeated→EnemyKillRewards.OnKill→StageCurrency.Grant` 순서다. Enemy의 체력0 재타격 거부와 Wave의 생존 집합 제거가 중복 이벤트를 막는다. 풀 반환/사망 완료는 다시 지급하지 않는다. 탈출은 EnemyArrived 경로로 처리하므로 처치 보상을 지급하지 않는다.

OnKill은 실행 중인 Wave와 생존/미승리 상태에서만 지급한다. 금액은 일반2·빠른2·보스100이며 현재 던지기 가격을 참조하지 않는다. 지갑 변경 콜백이 적을 반환/재사용할 수 있어 표시 위치를 Grant 전에 복사한다. Grant 도중 전투가 끝나면 새 획득 표시를 만들지 않는다. 실제 지급액을 사용하므로 정수 상한에서도 잔액/표시가 일치한다.

## 작업21 검증 (2026-11-18)

Unity6000.3.28f1 ThrowYut 씬 복사본 Play Mode **23개 검사 통과·검사 구간 런타임 오류0**. [결과](Verification/KillRewardVerification.json)·[검증 도구](../Assets/Editor/KillRewardVerification.cs)·[실제 코인 표시](Previews/KillRewards.png).

- 일반/빠른/보스를 처치하는 순간120→122→124→224,상단HUD224·표시+2/+2/+100을 확인했다. 중복 치명타/사망 완료에는 추가 지급하지 않는다.
- 남은 일반 적을 검증용 짧은 경로로 실제 탈출시켜 무처치 보상과 기존 완료60을 분리했다.224→284·하트9이며,다음 전투의 재사용 적을 처치하면286이다.
- 상한 직전 잔액에서2 중1만 지급/표시하고,승리/하트0/종료 Wave의 늦은 알림에는 지급하지 않았다. 유효 처치의 Grant 콜백이 즉시 Wave를 중단해도 해당 처치2는 한 번 지급하고 새 표시를 만들지 않았다.
- 기존 표시 배율1.6·입력 비차단·시간 경과 후 소멸을 확인했다. 기존 패배 중단17개 회귀도 통과·검사 구간 오류0이다(`Logs/DefeatStopAfterRewards.json`).

검증 중 편성은 일반2/빠른1/보스1로 바꾸며 최종 웨이브/즉시 승리 검증은 아니다. 실제 스테이지는 작업12의10웨이브 편성을 유지한다. 데이터/하트/적 위치/생성 간격/상한 잔액·승패 플래그·시간 설정은 메모리에서만 바꾸고 저장하지 않았다. 전체 빌드·천명전 배율·보스 즉시 승리 정산 순서는 후속 범위다.

검증한 변경 코드·씬·검증 도구의 SHA-256을 작업본과 대조했다. 기존 검증 복사본/캐시를 재사용하고 원본 에디터는 유지했다. 초기 검색 인덱스 예외는 검사 시작 전이며 오류0은 검사 구간 기준이다. 배치 재실행은 별도 복사본에서 `-executeMethod KillRewardVerification.ReimportAndRun -force-d3d11 -screen-width 1920 -screen-height 1080`을 사용한다. Logs/KillRewardVerification.json과 Verification/SpecialSummon/kill-rewards-task21.png에 결과를 쓰고 검증 편집기를 종료하므로 원본의 열린 에디터에서 직접 실행하지 않는다.

표시 크기는 이전의 1.6배다. Popup Scale 설정으로 코인·숫자·더하기 기호를 함께 조절한다.
