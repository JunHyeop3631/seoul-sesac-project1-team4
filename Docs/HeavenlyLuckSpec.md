# 천운부 구매 즉시 할인 — 작업36

천운부 가격100. 구매 확정 즉시 스테이지 동안 실제 윷 던지기 비용을20→16으로 바꾼다. 별도 사용/소비 조작은 없으며 보유와 구매 완료 이력을 유지한다. 인벤토리에는 적용 중을 표시한다. 가격 표시·실행 가능 잔액 검사·실제 결제·부족 강조는 같은 현재 비용을 사용한다.

구매 이력이 거래 알림 전에 확정되는 기존 구조를 이용한다. 천운부 효과는 구매 이력을 조회하여 적용 상태를 제공하고 별도 중복 상태를 저장하지 않는다. 다음 웨이브에도 유지하고 새 씬에서는 미구매/비용20으로 돌아온다. 보상 기준액은 바꾸지 않으며 일반/빠른 적2·보스100·일반 웨이브 완료60은 유지한다. 다른 효과37~39는 이번 범위에 추가하지 않는다.

## 실행 흐름

1. [HeavenlyLuckTalismanEffect.IsApplied](../Assets/Scripts/Turn/HeavenlyLuckTalismanEffect.cs)는 ShopPurchaseController의 천운부 구매 완료 이력을 조회한다. 기존 구매 거래가 잔액 알림 전에 이력을 기록하므로 별도 Purchased 이벤트 구독이나 중복 활성 플래그 없이 즉시 적용된다. 사용 실행기에는 보유형 상태 제공자로 등록하며 CanApply/TryApply는 항상 거부한다.
2. [TurnController.CurrentYutThrowCost](../Assets/Scripts/Turn/TurnController.cs)는 기본 상수 YutThrowCost20을 보존하고 적용 시16을 반환한다. CanThrowYut 잔액 검사·TryPayForYutThrow 실제 차감·부족 밝기·가격 숫자는 이 현재 비용을 함께 사용한다. 던지기 실행기는 기존4개 윷 검증과 IsThrowing 잠금 뒤 결제하므로 연출 중 재입력에도1회만 차감한다.
3. 인벤토리의 기존 itemUse.IsApplied 조회가 실제 상태를 받아 ‘적용 중’을 표시하며 사용 버튼은 숨긴다. 별도 사용/소비가 없고 창을 닫거나 웨이브가 넘어가도 보유/구매 이력이 남는다.
4. [HeavenlyLuckBuilder](../Assets/Editor/HeavenlyLuckBuilder.cs)는 씬에 효과를 추가하고 구매/사용 실행기·Turn을 연결한다. 던지기 가격 영역의 기존 고정20 숫자를 비활성화하고 같은 위치에 GoldNumberDisplay를 연결한다. 기존 코인 아이콘·버튼 크기·배치를 유지한다. 저장 후 재로드해 효과/가격 표시 참조를 검사한다.

- 구매 전 비용20·잔액19 거부/20 허용, 구매 재화99에서 할인 미적용, 실제 구매 버튼으로100 차감 후 잔액16/보유1개/할인 적용을 확인했다. 구매 잔액/성공 알림 안에서도 현재 비용·가격 표시가 이미16이다.
- 실제 천운부 선택 시 ‘적용 중’·사용 버튼 숨김·강제 사용 무소비를 확인했다. 충분한 재화로도 재구매/할인 중첩은 거부한다.

- 실제 다음 웨이브 준비에도 적용 표시와 비용16·1회 결제를 유지한다. 실제 일반 처치2·완료60과 최종 보스 처치100을 확인했다. 빠른 적의 보상 설정2도 유지한다. 보스 검사는 최종 웨이브 인덱스를 지정한 fixture이며1~10 전체 수동 완주가 아니다. 가격 검사에 집중하기 위해 일부 윷 결과를 메모리에서 설정/해제했다.
- 새 씬은 일반120/특별0/보유0/미적용/비용 표시20으로 초기화한다.
