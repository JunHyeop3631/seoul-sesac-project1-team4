# 적 종류별 이동 시간 (2026-11-18)

작업12에서 다시 내보낸 [사용자 지정 Google Docs 탭4](https://docs.google.com/document/d/1hI6NtOWNZ2KTU-vgrUT0q4KMR9PjlM2E5JoXmvvcwuU/edit?tab=t.blkk5zag95yu)의12장 이동과 등장 표를 기준으로 작업14를 대조한다. 같은 입구·출구의 닫힌 경로를 방해 없이 이동할 때의 값이다.

| 종류 | 일반 대비 속도 | 1배속 통과 시간 | 경로 길이 L의 속도 |
| --- | --- | --- | --- |
| 일반 | 1배 | 30초 | L/30 |
| 빠른 적 | 1.5배 | 20초 | L/20 |
| 보스 | 0.5배 | 60초 | L/60 |

## 현재 연결

기존 Enemy.cs와 세 프리팹에 이미 구현된 값을 유지했다. `lapDurationSeconds`는 일반30·빠른20·보스60이다. `Enemy.StartMoving`은 실제 경유점의 월드 좌표를 복사하고 마지막→첫 점을 포함한 닫힌 경로 길이 L을 구해 `moveSpeed=L/lapDurationSeconds`로 계산한다. 프리팹의 Move Speed=2는 이 경로에서 최종 속도가 아니다. Lap Duration Seconds가0인 기존 데이터만 Move Speed를 직접 사용한다.

`Enemy.Update`는 `moveSpeed*Time.deltaTime`을 이동 예산으로 사용하고 모서리 도달 후 남은 거리를 다음 구간에 적용한다. 따라서 일시정지와 게임 배속을 따르며, 마지막 경유점에서 출발점으로 돌아온 뒤 도착 콜백을 호출한다. 풀 반환 시 `OnDisable→StopMoving`이 경로/콜백/이동 상태를 비우고 다음 StartMoving에서 새 경로 길이를 다시 계산한다.

적의 속도/HP/공격·처치/탈출 승패는 서로 다른 조건이다. 작업14에서는 기존 속도 계산을 검증하며 보스 탈출 즉시 패배는 작업23에서 확인한다. 이번에 런타임 이동 코드나 프리팹을 다시 수정하지 않았다.

## 검증 방법과 한계

[EnemyMovementVerification.cs](../Assets/Editor/EnemyMovementVerification.cs)는 ThrowYut 씬의 실제 경유점과 실제 세 프리팹/풀을 사용한다. Enemy.Update를 직접 호출하거나 도착 시간을 계산식으로 대신하지 않고,정상 Unity 프레임에서 실제 도착 콜백의 게임 시간과 비배속 시간을 기록한다.

- 원래 경로1배속,1.5배 확대 경로1배속,원래 경로2배속·4배속을 측정한다.
- 같은 풀 인스턴스의 재사용·속도 재계산·입구 복원·도착1회·풀 반환 후 이동 중단을 검사한다.
- 별도 일시정지 구간에서 위치/체력/이동 상태 보존과 재개를 검사한다.
- 1배속의 원래/확대 경로는 검사 비용을 줄이기 위해 `Time.captureDeltaTime=.1`로 게임 시간 간격을 고정한다. 이 두 경우의30/20/60초는 시뮬레이션 게임 시간 기준이며 실제 컴퓨터에서60초를 기다리는 벽시계 실험은 아니다. captureDeltaTime은 비배속 실시간을 고정하지 않으므로 이 경우 비배속 시간과 통과 목표를 비교하지 않는다.
- 2배속/4배속은 captureDeltaTime=0의 정상 프레임으로 전환해 실제 게임 시간과 비배속 시간을 함께 측정한다. 통과 게임 시간30/20/60초와 비배속 시간15/10/30초·7.5/5/15초를 각각 비교한다. 전체 측정값은 결과JSON에 구분해 기록한다.

테스트 경로·시간 설정은 메모리에서만 변경하고 씬/프리팹은 저장하지 않는다. 종료 시 captureDeltaTime과 timeScale을 복구한다. 전체 빌드·실제 렌더링·피격 방해/공격·최종 승패는 이번 검증 범위가 아니다.

재실행은 별도 검증 복사본에서 배치 `-executeMethod EnemyMovementVerification.ReimportAndRun -nographics`다. 결과는 `Logs/EnemyMovementVerification.json`에 쓰고 검증 편집기를 종료하므로 원본의 열린 에디터에서 직접 실행하지 않는다.

## 실행 결과

Unity6000.3.28f1의 ThrowYut 씬 복사본에서 **100개 검사 통과·검사 구간 런타임 오류0**. [전체 측정 JSON](Verification/EnemyMovementVerification.json).

| 측정 | 일반 | 빠른 적 | 보스 |
| --- | ---: | ---: | ---: |
| 씬 경로 길이 | 31.8 | 31.8 | 31.8 |
| 씬 적용 속도(유닛/게임초) | 1.06 | 1.59 | 0.53 |
| 1배속 고정 게임 시간 완주(초) | 30.1 | 20.1 | 60.1 |
| 1.5배 확대 경로 고정 게임 시간 완주(초) | 30.0 | 20.1 | 60.0 |
| 정상 프레임2배속 비배속 시간(초) | 15.000 | 10.000 | 30.000 |
| 정상 프레임4배속 비배속 시간(초) | 7.500 | 5.000 | 15.000 |

경로 확대 시 길이47.7에 맞춰 속도도1.5배로 재계산됐다.1배속의 최대0.1초 차이는 고정 프레임 도착 판정 단위이며 통과 시간을1프레임 이내로 검증했다. 정상 프레임2/4배속은 게임 시간도 각각30/20/60초를 유지했다. 일시정지8프레임 동안 위치/체력을 유지하고 재개 후 이동했으며,모든 도착은1회만 발생하고 풀 반환 후 멈췄다.

검증한 Enemy.cs·검증 도구·세 프리팹·씬의 SHA-256이 작업본과 일치한다. 원본 에디터는 유지하고 검증용 복사본에서만 실행했다. 첫 실행의 검증 도구가 captureDeltaTime의 고정 게임 시간과 비배속 실시간을 동일시한 비교를 수정한 뒤 위 결과를 얻었다. 런타임 구현 결함으로 판정하거나 이동 코드를 수정한 것은 아니다. 초기 에디터 검색 인덱스 예외는 검사 시작 전의 로그이며 오류0은 실제 검사 구간 기준이다.
