# 웨이브별 적 체력과 이동 (2026-11-18)

2026-11-18 작업12에서 사용자가 지정한 [Google Docs 탭4](https://docs.google.com/document/d/1hI6NtOWNZ2KTU-vgrUT0q4KMR9PjlM2E5JoXmvvcwuU/edit?tab=t.blkk5zag95yu)를 다시 열어 내보낸 최신 본문의12장 표로 맞췄다. 이 표가 이전 체력2배 기록과 임시 에셋 조정값을 대체한다. 일반 적은1배속 한 바퀴30초, 빠른 적20초, 보스60초인 기존 이동 설정을 유지한다. 적 수·등장 간격·처치 보상은 이번 HP 변경에서 수정하지 않았다.

Wave1~Wave10의 Enemies > Health에서 웨이브별 개체 HP를 수정한다. Health가0이면 프리팹 기본 체력을 사용하는 기존 호환 경로다. 등록된10개 웨이브는 모두 명시적 양수 HP를 사용한다. 프리팹 기본 HP20은 이번에 바꾸지 않으며 실제 스테이지 HP는 위 표가 결정한다.

각 적 프리팹의 Lap Duration Seconds는 일반30·빠른20·보스60이다. Enemy.StartMoving은 시작 시 실제 경유점의 닫힌 경로 길이를 계산해 Move Speed에 길이/시간을 적용한다. 경로 크기가 바뀌거나 풀이 재사용되어도 다시 계산한다. Lap Duration Seconds가 0인 기존 데이터는 Move Speed 값을 직접 사용한다.

이동은 기존 Time.deltaTime을 사용하므로 일시정지와 게임 배속을 따른다. 걸음 애니메이션, 적 수, 등장 순서와 생성 간격은 이번 작업에서 변경하지 않았다.

체력 초기화는 풀 활성화 직후 해당 웨이브 값으로 적용되며 체력바는 출현별 최대 HP를 기준으로 계산한다. 피해의 소수점 계산은 유지한다.

작업12 검증 도구는 [WaveHealthVerification.cs](../Assets/Editor/WaveHealthVerification.cs)다. 최신 표의 개별 HP·종류별 수량·총 HP·씬의10개 데이터 순서를 고정 기대값과 대조하고,실제203기를 생성/피해/반환한다. 같은 풀 인스턴스의 재사용·기본값 복원·출현별 HP와 체력바·소수 피해·첫 적 즉시 등장을 확인한다. 검사용 생성 간격만 메모리에서 줄이고 씬/프리팹은 저장하지 않는다. 이동 시간 측정과 고정 혼합 순서·보스 즉시 승패·처치 보상은 이번 검증 범위가 아니다.

실행 결과: Unity6000.3.28f1의 ThrowYut 씬 복사본에서 **907개 검사 통과·검사 구간 런타임 오류0**,203기 생성 중200회는 같은 종류의 풀 인스턴스를 재사용했다. [결과 JSON](Verification/WaveHealthVerification.json). 기존 전투 시작 회귀29개도 통과·검사 구간 오류0이다(`Logs/BattleStartAfterWaves.json`). 검증 복사본의 코드·10개 데이터·씬과 작업본의 SHA-256을 대조했다. 기존 검증 캐시를 재사용하고 원본 에디터는 유지했다. 전체 빌드·체력바 화면 렌더링은 이번 검증에 포함하지 않는다. 초기 에디터 검색 인덱스 예외는 검사 시작 전의 로그이며 위 오류0은 실제 검사 구간 기준이다.

재실행: 별도 검증 복사본을 배치 `-executeMethod WaveHealthVerification.ReimportAndRun -nographics`로 실행한다. `Logs/WaveHealthVerification.json`에 결과를 쓰고 검증 편집기를 종료한다. 사용 중인 원본 에디터에서 직접 실행하지 않는다. 통과한 결과는 생성 순서가 기획의 고정 혼합 목록과 일치함을 뜻하지 않으며 그 조건은 작업13에서 연결한다.
